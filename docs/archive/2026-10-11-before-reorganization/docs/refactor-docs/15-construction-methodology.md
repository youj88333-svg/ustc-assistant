### 项目工作流标准

默认路径为：**Sol 确定契约与任务规格 → Luna 实现适合委派的小块并自测 → Sol 复核、集成和验收**。主代理 GPT-6.1 Sol 持续掌握项目上下文和完成状态，根据任务风险决定直接执行、委派或升级；简短工作直接完成，复杂实现可由 Sol 自行承担或委派 Sol 子代理。

| 角色与默认模型 | 思考强度 | 责任及适用范围 |
|---|---|---|
| 主代理；GPT-6.1 Sol | `max` | 收敛设计和未知项、维护契约、拆分及排序任务、实现关键边界、组织调试、审查差异、集成和最终验收；对项目交付负责 |
| 实现子代理；GPT-6 Luna | 固定 `max` | 实现输入/输出和失败语义已确定、修改范围小的任务，例如纯逻辑、映射、已有接口下的 UI 或合成测试；运行相关检查并交回实际结果 |
| 复杂任务子代理；GPT-6.1 Sol | 主代理按任务判断 | 处理跨层交接、并发状态、数据库原子性、平台生命周期或安全边界；规格难以独立确定时先完成设计/诊断，再安排实现 |
| 按需专家；GPT-6 Astra | 主代理按任务判断 | 分析 Sol 尚未解决的复杂问题，或独立复核重大架构、安全及数据取舍；由主代理核实和采纳结论 |
| 用户 | — | 决定产品范围、安全红线、数据保留承诺及可能损失已有数据的取舍；操作真实凭据、验证码和学校授权，提供相应人工验收 |

用户已授权主代理在已批准工作的范围内按本标准委派和选择模型，普通技术选择与修复直接推进。增加模型、代理或审查轮次须有具体待解决的问题；上表按任务选用，不要求每项工作经过全部角色。模型名称是本项目的选型约定，实际调用以可用配置为准；替换时记录原因，不声称未发生的模型调用。

**思考强度**：用户于 2026-10-10 将主代理 GPT-6.1 Sol 从 `xhigh` 调整为 `max`；后续所有 Luna 子代理继续统一使用 `max`，包括采用其他 Luna 版本或承担审查任务时。其他子代理由主代理根据任务复杂度、风险和可用强度决定。创建子代理时显式填写模型与 `reasoning_effort`，接续任务沿用该配置；任务交接保留实际模型与强度，不能用工具默认值或上下文继承代替 Luna 的 `max` 要求。

**任务规格与交接**：较大任务只维护一份任务单，按依赖拆成可单独验收的小块，每块写清下列信息；短任务可在派发消息中说明，无需另建文件。

- 用户可见目标、范围与不做的扩展、尚未证实的假设，以及所依赖的当前文档/契约。
- 输入/输出、接口和必要数据形状；状态、字段归属、不变量及失败/取消/重复执行的确定结果。
- 允许修改的文件与禁止触碰的资产、必要依赖、前序完成条件；共享接口及装配由谁负责。
- 验收行为和关键反例、相关检查命令、完成条件；返回修改摘要、实际检查结果和剩余问题。

**设计依据必须显式交接**：每份施工规格与子代理提示词都从 `docs/README.md` 导航，列明对应的 07–15 现行条款、已经批准的修订及本切验收条件；不能只写功能目标，也不能让实现者沿用历史正文中的旧分支、旧里程碑或旧通过结论。设计冲突先交回 Sol，涉及产品范围、安全红线或数据保留承诺的改变仍由用户决定。此要求于 2026-10-10 根据用户对提示词的提醒补充，适用于整个项目后续工作。

Sol 把规格写到实现者无需猜测关键业务决定的程度。详细程度随风险调整，保留实现者对局部代码结构的选择；不预先把整个项目展开为逐行伪代码。实施中发现接口缺口、规格矛盾或必须扩大修改范围，Luna 先将具体问题交回 Sol；Sol 修正契约或自行诊断，已有小块随更新后的规格推进。

**协作与验收**：只并行契约已确定、依赖独立且写入文件不重叠的任务。共享接口、入口装配和集成修改由主代理安排单一写入者，不能靠各实现者自行协调相互覆盖。子代理仅接收必要设计片段、文件和验收要求；交接以实际差异、检查结果和未解决问题为准，不建立额外派发插件、重复报告或固定多轮流水线。

Luna 自测之后，Sol 按用户行为和契约独立检查代码与结果，核对失败、取消、恢复及适用的安全/事务边界，不能仅重跑实现者照着代码写出的测试就宣告验收。测试是否先写按风险决定，不统一要求所有任务 TDD；测试不以数量为目标。简单修改由主代理完成相关检查，关键边界按需要用不继承实现者结论的上下文独立复核。出现反复返工或跨模块问题时升级到 Sol，必要时再用 Astra 分析，避免让 Luna 在不明确规格下持续试错。

**额度与反馈**：以完成并验收一个切片的总消耗评估效率，计入计划、上下文、实现、审查和返工；控制不必要的长规格、重复上下文、工具输出及重审。可取得用量时据实记录，否则只记录可核实的结果，不宣称固定节省比例。此前一次临时快照导入试验中，Sol 定规格、Luna 实现、Sol 复核，9 组独立验收首次全部通过，无需实现返工；临时目录和两个实验文件已清理。该结果支持边界明确的小任务采用此分工，尚不能证明整个 M0 的额度收益或正式验证通过。

### 设计验证先行

先确认影响可行性的真实来源身份、导航、只读响应及保留的平台控制，再完善必要模型与接口。采用新合成页面做可丢弃最小验证；真实站点由用户协助，密码、验证码和授权由用户操作。验证不能用假身份证据补成通过，也不能等全部产品实现后才首次验证；真实观测入口不等待 CAL 修复、完整协议隔离或整体设计冻结。

验证按 13 的分段触发覆盖：本地 M0 先验证目录排他、合成产物封存与事务交接、版本守卫及取消/提交裁决；真实浏览器切片验证 initial/recovery 许可认领、重认证、文档守卫、顶层/frame 导航、弹窗/下载/权限申请/外部协议控制、固定采集操作、Agent 无任意浏览器执行权、排空和真实清理；凭据切片验证保护与原子提交。用户实际验收登录、身份、采集、取消、关闭和清理。

浏览器装配遵循 07 DR-ADR-09：不主动注入 CAL、不安装全协议 DNR/CSP 防护扩展、不一律禁止 Worker、不替换 WebRTC，尊重已有策略，接受页面及依赖脚本的正常后台网络活动。来源特定常规请求规则仅按可靠且兼容性已证的范围采用；未知后台流量或全协议覆盖不足单独不使来源 unavailable。应用自有 HTTP/模型请求仍限定目标、必要字段和授权，主动学校业务只读。

V-01/V-03 在来源适配实现前尽早真实观测、启用前补齐；身份、响应/完整性或保留控制未通过的来源仍 unavailable。CAL 修复、补丁运行时资格及全协议漏拦回归正式移出 M0、真实观测入口、首版冻结和发布门槛，不主动追版本或修复该路线，原失败与工具留档，实际同类故障才按兼容性处理。详细字段按归属与阶段确认，合成与真实证据分开，不以文档宣布能力通过。

依据 14 第 8 节，本地 M0 范围基线已确认，可先创建 Flutter 工程；不再要求先取得包含所有真实来源的整体冻结。按本节工作流维护必要任务规格与检查结果，使用普通文档和 Git；不加载旧插件、任务派发模板、审查包或代理流水线，不创建无关分支/工作区，不直接复制旧实现、测试、fixtures 或 CI。

### M0 与后续切片

M0 从已确认的核心契约实现一条可运行细切片：C5/P 取得可丢弃目录排他 → 新合成来源 → C2 作业仲裁 → C1 规范化、完整性检查与产物封存 → C3 可丢弃数据库事务导入 → C5 显示安全结果，并能演示取消、稳定失败及提交后待办。时钟、错误、隐私、账号及 generation/epoch 守卫、事件顺序和基本装配进入该切片；正常收口不撤销封存产物，取消/维护拒绝未提交旧产物，提交后不能报无修改。M0 数据不进入正式用户目录，不拿真实账号或旧数据库做骨架样本。

M0 的具体协作顺序如下，后续里程碑沿用细切片交付方式：

1. **按已批准范围启动**：Sol 依据 13/14 的本地 M0 准入确认工具链与最短链路；已有实验只作为语义和能力线索，Dart/Drift/Windows 实现另验。真实来源及浏览器未知项由 Sol 处理，学校操作由用户完成；它们分别约束对应能力启用，不再阻止本地骨架开工。
2. **写一份可执行计划**：Sol 定义最短端到端链路、模块接口、不变量、失败结果、文件归属及依赖顺序，写出每块验收条件。目录所有权、会话许可、取消/提交及凭据/业务事务等跨层边界由 Sol 负责。
3. **分块实现并及时集成**：Luna 实现已确定接口下的规范化、简单映射、结果展示或合成反例等小块；Sol 处理关键边界与装配。前后依赖按顺序推进，独立块才并行；每个小块完成即接入切片检查，尽早跑通链路。
4. **主代理关闭切片**：Sol 独立验收正常、失败、取消、重启和适用的事务/安全反例，修复集成问题；关闭里程碑时执行 analyze/test/build 全套，另记需要的真实人工验收。仅以子代理任务完成不能关闭 M0。

# 15 施工方法论（Construction Methodology）

> 产出日期：2026-08（本会话） ｜ 状态：**生效**（用户已重认设计 go，M0 按本文档开工）
> ｜ 定位：0–6 层设计之后的**施工纪律文档**。本文不改变 07–13 的任何契约、风险、
> 关闭标准或红线；只规定"怎么写、按什么顺序写、每一块怎样算完成"。
> ｜ 优先级：与 07–13 冲突时，红线与四铁律（07）最高，接口契约（09）次之，
> 本文只调整施工顺序与完成定义（DoD），不改语义。

## 1. 为什么要这份文档：旧房病根诊断

旧房 v2 试做的失败模式有明确记录：**最后一批提交全部在补"导航就绪归属、URL/事件
顺序、ready 握手"等横切问题**。病根不是"逐块实施"本身，而是三个叠加：

1. **横向铺开、集成押后**：共享基础设施被当作单链路附属品硬做，全链路第一次跑通
   发生在里程碑末段，边界时序问题集中爆发，debug 只能跨层猜测。
2. **契约没有机器强制**：接口只写在文档里，生产者和消费者各写各的，合并时才
   发现错位。
3. **横切关注被当作"最后再补"**：时区、事件顺序、错误码、可观测性没有进入每块
   的完成定义，于是堆积成"最后一批补丁"。

对策不是"不许逐块做"（M0–M8 分里程碑是既定路线，必须保留），而是换成成熟的
**骨架先行 + 竖切交付 + 契约护栏 + 绞杀榕开关 + oracle 安全网**。

## 3. 组合后的施工纪律（六条）

### 纪律 1：骨架先行——M0 从"空骨架"升级为"可运行骨架"

M0 不再只是空工程 + CI，而是让一个 **fake source 打穿第 0–2 层定义的全链路**：

```text
SourceChannelRegistry(每源一通道开关, fake 为第一源)
  → NativeFakeGateway ──产出── SourceBundle 1.0 字节流（09 契约形态）
  → JobArbiter 雏形（作业生命周期端口）
  → 采集引擎端口（EnginePort：事件顺序/ready 语义先以 fake 驱动串通）
  → normalize → validate → ImportPort（M0 用 throwaway skeleton.db，不建 v7/v8 正式表）
  → 结果查询（返回导入汇总 + 错误码）
```

- **fake source 是正式测试资产**：与 M2 复用的 loopback fixture 服务器同一路线，
  M0 先落最简版，M2 增厚为完整状态机夹具。
- **开关从 M0 就有**：`source → channel(native|python)` 配置表默认指向 Python
  通道，fake 源指向 native 通道。此后任何来源拨开关都有代码路径可走，
  不靠文档约定。
- **横切项第一周点亮**：Asia/Shanghai 时钟注入、结构化日志、错误码枚举、
  依赖注入/可测试装配，全部进入 M0 骨架而非事后补。
- M0 门禁不变的部分：analyze/test/build 全绿；**新增部分**：fake 源 E2E smoke
  契约测试必须通过（这就是 Walking Skeleton 的"骨架能走"判据）。
   M1 起 fake 通道的 LeaseStamp.source 与 bundle.source 恒为 `ustc_jw`，路由键 `fake`
   只决定通道选择，不再作为 stamp.source 使用（M0 遗留项关闭）。

### 纪律 2：竖切交付——每里程碑一条完整切片，引擎绝不随链路附属开发

- M2 内部顺序固定为：**契约测试 → 引擎在 loopback 上做完整（状态全集、事件顺序、
  可观测）→ JW 适配器 → oracle 逐字段对比 → 真实教务人工验收**。
  引擎先对 fake 稳定，再插第一条真实适配器；任何横切缺陷在 fake 阶段修掉，
  成本最低。
- M3/M4 每条来源都是一个竖切，各自独立过 gate、独立拨开关；未切的来源继续走
  Python 通道，互不阻塞。
- 禁止"先把某层全部做完再进入下一层"的横向马拉松。

### 纪律 3：契约先行——每个里程碑开工先写可执行契约测试

- 从 09 的 CT 矩阵抽取本里程碑涉及的契约，先写契约测试（生产/消费两侧都对着它
  开发），后写实现；测试不过，该块不算开工完成。
- 契约测试放在 CI 常驻，合并即验证。契约变更走 09 文档 → 契约测试 → 实现的
  顺序，禁止先改实现再改文档。

### 纪律 4：绞杀榕开关——逐源接管、随时可退

- `NativeXxxGateway / PythonXxxGateway` 并存由**配置表 + 运行开关**强制，
  同源同刻单通道（四铁律之一）在 ChannelRegistry 内断言。
- 每条新链路：fixture 全流程 + oracle 对比通过后才允许拨 native；
  拨开关后保留 Python 通道与回拨能力，直到 M7 统一删除。
- 每里程碑打 tag（如 `m0-skeleton`、`m2-jw-native`），回退 = 拨开关 + 回 tag。

### 纪律 5：Golden Master + oracle 常驻 CI

- 冻结 fixture 样本集（R-08）只增不修；Python oracle 对比
  （`compare_jw_bundles.dart` 路线）纳入 CI 常驻，**不是里程碑结束时跑一次**。
- 新旧输出任何差异必须落在登记表：要么是已登记的新房修复，要么是 bug。
- 补充：旧房未覆盖的行为以 07–13 契约为准，不以旧房 bug 为准（oracle 不是宪法）。

### 纪律 6：高风险迁移用 Mikado、日常用短分支

- M1 v7→v8 迁移器、M7 Python 退役：按 Mikado 方法拆分依赖图，每步保持
  analyze/test/build 全绿、可回退。
- `rewrite/flutter-native` 长分支内部：**每个任务短功能分支 + 当日合入**；
  任何合并进长分支前三件套全绿。禁止长任务分支攒成大集成。

## 4. 每切完成定义（DoD）——直接回应"最后一批补横切"

每个竖切（含 M0 骨架）只有同时满足以下全部才算完成，**横切项当切当场勾完**：

- [ ] 功能路径跑通（本切范围全链路）；
- [ ] 本切涉及的 09 契约有契约测试且 CI 通过；
- [ ] 时间：统一 Asia/Shanghai（时钟注入，不裸用本地时区）；
- [ ] 隐私：本切新增文本经 `inspectUserText` 路线或等价预检；隐私拒绝走
  `privacy_rejected` 错误码；
- [ ] 错误：全部可恢复失败路径走注册错误码，无裸 `StateError`/吞异常；容器内部不可恢复的
  编程不变量允许 fail-fast，但必须在 `JobExecutor` / C2 边界捕获、归一并完成资源收口，
  不得作为未捕获异步异常或裸异常到达调用方；
- [ ] 审计：本切写操作（如有）审计可追溯；
- [ ] 可观测：本切关键转移有结构化日志（事件顺序/状态转移/耗时）；
- [ ] 账号隔离：本切数据访问带 account 分区语义（骨架期允许用 fake account 占位）；
- [ ] analyze / test / build 全绿；
- [ ] 本切范围内的风险（13 号）勾选或登记新风险，关闭标准不被降级。

## 6. 禁止事项（反模式清单）

1. 禁止横向马拉松：不得"做完存储层再做引擎层"而不跑端到端。
2. 禁止集成押后：任何一块超过一天未合入 `rewrite/flutter-native` 长分支视为集成债。
3. 禁止横切攒尾：DoD 中任何一项未勾，该切不算完成、不得拨 native 开关。
4. 禁止 fixture 漂移：冻结样本只增不修；修 fixture 必须同 commit 改登记表。
5. 禁止契约单向变更：改接口先改 09 + 契约测试。
6. 禁止在 main 写重构代码：代码只进 `rewrite/flutter-native`；设计文档可进 main。
7. 禁止以自动测试冒充人工验收：学校页面真实验收当场做（07 §2.3-1），
   不攒到最后。
