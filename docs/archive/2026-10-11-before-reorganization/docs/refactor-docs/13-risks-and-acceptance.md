### 证据与隐私要求

自动测试使用新构造的合成数据和本机隔离页面，不访问真实学校网站；用户负责密码、Key、验证码和授权确认。真实观测只记必要来源版本、业务形状、安全布尔结论、计数和结果，不记录账号值、Token、Cookie、资源 query、原始响应或浏览器会话资产。用户显式要求的私有原始资料仍不进入 Git 或日志。

每项记录自动结果、真实人工结果与尚未执行部分；验收失败保持失败，重新尝试另记结果。旧测试数量、源码行号和旧关闭结论不参与本分支放行。可行性验证代码可丢弃，不直接成为产品实现或导入旧 fixtures。

### R-21 WebView2 导航策略的字面前缀匹配与 dot-segment（carried risk）

- **风险描述**：`NavigationPolicy::Allows` 是字面路径前缀匹配（`PathMatches`），
  不做 dot-segment 归一化：`<允许族>/…/../…` 这类未归一化 URL 会作为字面前缀
  成员被放行，这一点在 `windows/test/navigation_policy_test.cc`
  （`YoungProfileRejectsEveryUnobservedOrTrickyTarget`）中被显式断言并注明理由。
  归一化后的逃逸目标（如 `/etc/passwd`）不在任何允许族内，会被拒绝；
  percent-encoded 形式仍留在同一主机与同一族内。两种情况下 authority 都无法被
  改写（scheme/authority 规则保持不变，query/fragment 从不参与判定），所以逃逸
  目标只可能是已允许主机上的另一条路径——本项登记为"有界风险"，不是阻断项。
- **未决问题（M3 Task 17 修复轮 2 回写）**：WebView2 实际交给
  `NavigationStarting`/`WebResourceRequested` 的 URI，对这类导航是归一化形式还是
  原始字面形式。**现有证据（两条实测事实，均已自动断言）**：
  1. 匹配器一侧：字面前缀会放行未归一化的 `..` 形态——生产 profile 侧已在
     `navigation_policy_test.cc`
     （`YoungProfileRejectsEveryUnobservedOrTrickyTarget`）断言；Debug loopback 行
     侧在 `ResolveRequestKeepsLoopbackDebugOnlyAndBounded` 中同样是显式
     `EXPECT_TRUE`
     （`http://127.0.0.1:<port>/login/sc-wisdom-group-learning/../evil`），紧邻其
     后的归一化形态 `/evil` 断为拒绝。
  2. 引擎一侧：`app/integration_test/m3_native_young_loopback_test.dart`（R-21 用例）
     在**真实 WebView2** 中双向实测该调用顺序——对照用例把一段导航到"归一化后落在
     允许且可服务页面"的 `..` URL，页面确实加载（fixture access log 有记录）；判别
     用例导航到 `.../login/sc-wisdom-group-learning/../../nope/deep`（字面形态以
     `/login` 开头、归一化后为 `/nope/deep`），结果为 `navigation_blocked` 且该请求
     **从未到达 fixture**。即：策略收到的是**归一化后**的 URL。
- **这两条证据的射程（不得夸大）**：合起来**足以支撑导航路径本身，并足以把风险约束
  在有界区间**（仅同源、非阻断），但**不足以关闭本项**——只覆盖一种形态、只覆盖
  loopback origin、只经 `loadUrl`，未覆盖真实站点重定向图与 `WebResourceRequested`
  的其它 resource context。**R-21 的关闭标准仍是 Task 18 的真实站点观测**；在结论
  落档前**不得据此放宽任何允许行**。
- **历史来源**：原重构分支 M3 Task 10 实现与评审及其修复轮；当时任务约定禁止
  改动共享匹配器（会改变 JW 的匹配语义），因此当时没有做归一化加固。
  本分支重新评估该风险，不继承旧任务的实施限制或通过结论。
- **触发里程碑**：M3 Task 18 真实站点验收（Young schedule/enrolment 真实登录与
  采集）。
- **验证方式**：真实验收时按红线先取证后判定——记录被拒绝/放行的导航安全诊断
  目标（origin + path，query/fragment 已剥离），确认是否存在未归一化的 `..`
  形态到达策略层；据观测结果决定是否新增最窄加固与归一化回归。
- **关闭标准**：Task 18 观测结论落档（按"有界、接受"关闭，或另立加固任务并补
  回归测试）；在结论落档前不得据此放宽任何允许行。
