## 当前验收边界

- 普通 WebView 不主动注入 CAL，不安装为全协议封闭而设的 DNR/CSP 防护扩展，不一律禁 Worker，不以 JS 替换 WebRTC；尊重页面已有策略，接受页面及其依赖脚本的正常后台网络活动，不承诺全部协议白名单或零外联。
- 验收保留的导航/frame、弹窗、下载、权限申请及外部协议控制、固定采集操作与 Agent 无任意浏览器执行权，以及分区/文档关联、凭据保护、取消与提交、排空真清理。来源特定的常规请求规则只在可靠且兼容性已验证时采用；应用自有 HTTP/模型请求仍限定目标、字段和授权。
- 真实入口验证实际登录、服务端业务身份、原目标恢复、正确采集、取消/关闭/清理及保留控制。未知后台流量或全协议覆盖不足不单独阻止来源启用；未验证身份/响应/完整性及保留控制仍使来源 unavailable。实际同类崩溃才按普通兼容性故障处理。

## 历轮前置实验记录

以下任务、命令与未放行裁决保留其执行当时的范围。严格 CAL 增强路线已退出首版，旧“继续修复／等待候选／M0 不放行”的要求由上方当前边界替代；没有新增实验通过或产品验收。

## 目标与分工

- 主代理 GPT-6.1 Sol / xhigh：关键事务模型、独立验收、真实来源判断、证据回填及准入结论。
- Windows 子任务 GPT-6.1 Sol / high：直接使用 Windows WebView2 SDK 做隔离平台实验；原生生命周期和安全约束需要跨层判断。
- 纯模型子任务 GPT-6 Luna / max：确定契约下的来源稳定身份、字段覆盖、北京时间和重复例外逻辑。
- 用户：真实学校登录、验证码和授权；确认需要清点的业务资产范围。

## 范围与边界

所有自动实验只访问本机合成页面、合成业务数据和独立临时数据库。真实学校只能由用户在显式启动的可见候选窗口中操作。密码、账号值、Cookie、Token、认证 header/body、资源 query、原始响应和会话资产不进入日志或 Git。浏览器密码采用用户手填；未经文档级原子投递证明，不开启应用填密能力。

平台候选是直接使用 WebView2 原生 SDK 的 P 适配能力；本实验的 .NET 宿主只是 SDK 验证工具，产品仍按 Flutter/Dart 路线，实际 Flutter 插件装配须另验。每个随机实验根取得目录所有权后才打开分区/数据库，所有删除只允许已验证处于该实验根的目录，不访问系统浏览器或旧分区。

## 文件归属与执行

`windows/` 由 Windows 子任务单独写入；`model/pure_model.py` 及 `model/test_pure_model.py` 由 Luna 单独写入；事务实验、独立验收和本文件由主代理写入。共同契约改变先返回主代理。`.runtime/` 是忽略的构建和合成资产目录；依赖缓存可只读使用，不引入旧工程源码。

验收覆盖目录双实例/崩溃释放、浏览器分区隔离和重启、文档/导航/frame/迟到回调、自动请求/弹窗/下载、资源排空和真清理、DPAPI；模型覆盖稳定身份、改时关联/覆盖保留、完整性、缺失、操作回执/重放冲突、取消/提交竞争、同步后撤销、凭据/业务/许可/审计事务以及中途退出。未验证的来源特定完整性和外部稳定 ID 仍保持未知。

每次执行记录环境、命令、安全结果、失败和未执行范围；子任务自测由主代理独立检查。真实人工证据与合成自动结果分开，任何 V 项均不能仅凭文档/API 存在关闭。完成适用实验后回填 13 和 14；只有关键准入条件成立才记录新冻结并开始产品 M0。

## 出站约束续验任务

2026-10-09 用户要求继续。目标是验证原生 `Connection-Allowlist` 配合 DNR、CSP worker guard 的覆盖和可用性，再决定是否具备真实观测入口；不在此阶段放宽范围或安全承诺。

- **实施与文件归属**：GPT-6.1 Sol / high 负责 `windows/WindowsProbe.cs`、`windows/run.ps1`、平台报告及新 CAL 证据；GPT-6 Luna / max 只负责 `https_fixture/fixture.py` 和其说明；GPT-6 Astra / high 只读核对官方网络实现与具体难点。主代理 Sol / xhigh 负责策略判断、依赖准备、独立验收和总报告。模型目录本轮不改。
- **外部依赖**：本机合成 HTTP/3 阳性服务使用隔离安装的 aioquic 1.3.0 及[版本记录](https_fixture/requirements-pinned.txt)，仅位于 `.runtime/transport-deps`，不进入产品依赖，不修改 Conda 或用户证书库。此次安装沿用用户已配置的清华 PyPI 镜像和代理。
- **未知项**：当前 Runtime 是否完整实施 CAL；不同页面上下文、加载期与跨重启表现；TURN TCP 与 WebTransport 是否仍会联网；CAL 原响应头及重定向语义能否保守处理；真实学校是否依赖被禁的 Worker。
- **验证**：新 UDF 在导航前启用静态策略；未保护对照须证明 STUN/TURN TCP/WebTransport 实际联网。CAL 尝试须完成并有正常 HTTP 阳性，零接收与 API 存在都不能单独记通过。另以同一 HTTPS `/query` 的 GET 成功和真实 WebTransport 握手/固定 datagram 往返，验证 DNR CONNECT 拒绝是否在任何到包前生效。覆盖普通/继承 frame、重启、原 CSP、排空和真删除；仅用本机合成服务。
- **完成条件**：主代理独立复现并记录失败和限制，回填 V-02；兼容性、来源身份与必要业务契约仍由用户辅助真实验证。CAL 单主文档 STUN 实验已通过，但在两次普通同源文档导航后，单次 RTC 构造也触发原生渲染进程崩溃；该反例不需要 frame、Worker、WebTransport 或第二个 RTC。不能据此放行或关闭 V 项，也尚未确认 Chromium 内部根因。CAL `set` 不自动保留原站政策，真实入口前必须解决；学校真实凭据不进入本轮自动实验。

本轮续验收口：主代理普通导航后 RTC 的独立轮为 **18 pass / 12 fail / 5 info / 1 not_run，退出 1**，四组 CAL 首次/重启仍崩溃。HTTPS 服务的控制与停止缺口修复后，最终独立轮为 **107 pass / 0 fail / 31 info / 1 not_run，退出 0**，五类上下文同 URL 的 GET/WT 阳性与 CONNECT 零接收分别成立。两者排空与合成分区真删除均通过；原生清点分区、临时凭据与已知实验 helper 均为 0，7897 日常代理未修改。结果、源文件指纹、保留失败与独立服务验收见[续验元数据](evidence-continuation-review.json)和[平台报告](windows/README.md)。本轮验证有可审查结论，V 项与真实入口、整体冻结及产品 M0 的未放行状态不变；下一步集中处理平台后续文档 RTC 生命周期及尚未证明的策略边界。

### 导航后 RTC 崩溃定位与修复

用户随后明确要求确定问题并修复、询问 Astra。主代理 Sol / xhigh 接手平台源码与集成；Astra / xhigh 仅读当前实验和官方实现，提出可验证因果与修复方案。范围限 `windows/WindowsProbe.cs`、`windows/run.ps1`、平台说明及新的脱敏证据，既有失败文件保留；必要诊断工具及运行时只放 `.runtime`，不改系统代理或用户浏览器。未知项为 CAL 策略与文档/native binder 生命周期的关系，以及应用层可实施的修复是否保持网络约束。验证须保留未保护真实联网阳性、保护首次及后续文档/重启的正常执行与零接收，覆盖 frame/继承文档及现有 HTTP/WT/Worker 行为，完成排空与真删除。关闭条件是有可审查的原因及可重放修复回归；禁用 CAL、JS 替换 RTC、崩溃零包或无阳性不算修复，不凭本子任务关闭整体 V-02/真实来源/M0。
