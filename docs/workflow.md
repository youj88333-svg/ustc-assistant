# 15 本分支精简施工方式

## 本分支当前规则

本标准于 2026-10-09 经用户要求建立。用户要求“总结一下刚才关于工作流的讨论并记录作为整个项目工作流标准”。本节据此成为设计、前置验证、M0 及后续实现、调试和验收的统一工作方式，替代此前默认单 agent 独立施工的约定；根目录 [AGENTS.md](../AGENTS.md)保存执行摘要。新工程只在 `E:\107\.worktrees\rewrite\design-reset` 修改。当前阶段查看 [状态页](status.md)，具体批准查看 [决策登记](decisions/README.md)。

### 项目工作流标准

默认路径为：**Sol 确定契约与任务规格 → Luna 实现适合委派的小块并自测 → Sol 复核、集成和验收**。主代理 GPT-6.1 Sol 持续掌握项目上下文和完成状态，根据任务风险决定直接执行、委派或升级；简短工作直接完成，复杂实现可由 Sol 自行承担或委派 Sol 子代理。

| 角色与默认模型 | 思考强度 | 责任及适用范围 |
|---|---|---|
| 主代理；GPT-6.1 Sol | `max` | 收敛设计和未知项、维护契约、拆分及排序任务、实现关键边界、组织调试、审查差异、集成和最终验收；对项目交付负责 |
| 实现子代理；GPT-6 Luna | 固定 `max` | 实现输入/输出和失败语义已确定、修改范围小的任务，例如纯逻辑、映射、已有接口下的 UI 或合成测试；运行相关检查并交回实际结果 |
| 复杂任务子代理；GPT-6.1 Sol | 主代理按任务判断 | 处理跨层交接、并发状态、数据库原子性、平台生命周期或安全边界；规格难以独立确定时先完成设计/诊断，再安排实现 |
| 按需专家；GPT-6 Astra | 主代理按任务判断 | 分析 Sol 尚未解决的复杂问题，或独立复核重大架构、安全及数据取舍；由主代理核实和采纳结论 |
| 用户 | — | 决定产品范围、安全红线、数据保留承诺及可能损失已有数据的取舍；操作真实凭据、验证码和学校授权，提供相应人工验收 |

用户已授权主代理在已批准工作的范围内按本标准委派和选择模型，普通技术选择与修复直接推进。增加模型、代理或审查轮次须有具体待解决的问题；上表按任务选用，不要求每项工作经过全部角色。模型名称是本项目的选型约定，实际调用以可用配置为准；替换时记录原因，不声称未发生的模型调用。

**思考强度**：用户于 2026-10-10 将主代理 GPT-6.1 Sol 从 `xhigh` 调整为 `max`；后续所有 Luna 子代理继续统一使用 `max`，包括采用其他 Luna 版本或承担审查任务时。其他子代理由主代理根据任务复杂度、风险和可用强度决定。创建子代理时显式填写模型与 `reasoning_effort`，接续任务沿用该配置；任务交接保留实际模型与强度，不能用工具默认值或上下文继承代替 Luna 的 `max` 要求。

**任务规格与交接**：较大任务只维护一份任务单，按依赖拆成可单独验收的小块，每块写清下列信息；短任务可在派发消息中说明，无需另建文件。

- 用户可见目标、范围与不做的扩展、尚未证实的假设，以及所依赖的当前文档/契约。
- 输入/输出、接口和必要数据形状；状态、字段归属、不变量及失败/取消/重复执行的确定结果。
- 允许修改的文件与禁止触碰的资产、必要依赖、前序完成条件；共享接口及装配由谁负责。
- 验收行为和关键反例、相关检查命令、完成条件；返回修改摘要、实际检查结果和剩余问题。

**设计依据必须显式交接**：每份施工规格与子代理提示词都从 `docs/README.md` 导航，列明对应的 07–15 现行条款、已经批准的修订及本切验收条件；不能只写功能目标，也不能让实现者沿用历史正文中的旧分支、旧里程碑或旧通过结论。设计冲突先交回 Sol，涉及产品范围、安全红线或数据保留承诺的改变仍由用户决定。此要求于 2026-10-10 根据用户对提示词的提醒补充，适用于整个项目后续工作。

Sol 把规格写到实现者无需猜测关键业务决定的程度。详细程度随风险调整，保留实现者对局部代码结构的选择；不预先把整个项目展开为逐行伪代码。实施中发现接口缺口、规格矛盾或必须扩大修改范围，Luna 先将具体问题交回 Sol；Sol 修正契约或自行诊断，已有小块随更新后的规格推进。

**协作与验收**：只并行契约已确定、依赖独立且写入文件不重叠的任务。共享接口、入口装配和集成修改由主代理安排单一写入者，不能靠各实现者自行协调相互覆盖。子代理仅接收必要设计片段、文件和验收要求；交接以实际差异、检查结果和未解决问题为准，不建立额外派发插件、重复报告或固定多轮流水线。

Luna 自测之后，Sol 按用户行为和契约独立检查代码与结果，核对失败、取消、恢复及适用的安全/事务边界，不能仅重跑实现者照着代码写出的测试就宣告验收。测试是否先写按风险决定，不统一要求所有任务 TDD；测试不以数量为目标。简单修改由主代理完成相关检查，关键边界按需要用不继承实现者结论的上下文独立复核。出现反复返工或跨模块问题时升级到 Sol，必要时再用 Astra 分析，避免让 Luna 在不明确规格下持续试错。

**额度与反馈**：以完成并验收一个切片的总消耗评估效率，计入计划、上下文、实现、审查和返工；控制不必要的长规格、重复上下文、工具输出及重审。可取得用量时据实记录，否则只记录可核实的结果，不宣称固定节省比例。


### 设计验证先行

影响可行性的来源身份、导航、响应和平台控制尽早确认。自动检查使用新合成/loopback/临时资产；真实学校由用户辅助，应用主动提供凭据的使用遵循已批准认证契约，挑战与额外授权仍由用户完成。合成与真实证据分别记录，不用候选探针或页面可达替代生产身份/许可。

验收按证据分工：Sol 负责可重复的工程检查、已授权公开来源的受控契约核对，以及固定资料从制作到实际载入/检索的完整链路。用户负责范围/保留等取舍、需要本人操作的登录与授权、无法由合成证据替代的个人业务对应关系，以及正式产品的使用判断；不要求用户重复已经覆盖的机械操作。仅供内部验收的临时界面不默认增加一轮用户体验门槛，真实使用体验在对应产品接入阶段安排。

公开内容核对与自动测试分开：测试仍只用合成/loopback/临时资产且不访问真实学校。已批准公开资料可通过明确启动的开发验核程序，在独立临时数据库中验证实际随包文本；不读正式业务或认证资料、不联网获取新内容，不把资料正确载入等同于政策现行。阶段关闭仍根据实际证据与用户决定记录，取消重复人工操作不等于伪记用户验收通过。

按 [13 的触发时机](quality/13-risks-and-acceptance.md) 分段验证；首版浏览器边界遵循 [07](architecture/07-constitution.md)，具体来源遵循 [来源参考](reference/sources/README.md)。未成立的来源能力保持不可用，局部通过不关闭整体 V 项。

### 切片与文档交接

1. Sol 从 [文档入口](README.md) 阅读当前设计、来源契约与风险，确认已批准范围。
2. 较大阶段只维护 `milestones/<阶段>/plan.md` 一份任务单，明确目标、未知项、接口与不变量、文件归属、依赖、验证和完成条件。
3. 依赖顺序清楚后安排小块实现并及时装配；阶段过程按切片写入 `records*`，不同事实不反复追加到设计正文。
4. Sol 独立复核并运行相关检查；里程碑关闭前完成 analyze/test/相关 Windows/build 全套，以及范围所需的真实人工验收。
5. 用户验收和关闭写入 `acceptance.md`，当前结论更新状态页。未观察项继续在 13 登记，不伪报关闭。

相关检查通过后，在可回退的小阶段建立本地 Git 提交，避免阶段成果长期只留在工作树。文档整理和工程实现按实际边界分开；提交说明包含行为变化、检查及仍待真人验收的范围，构建目录、临时原件和私有资产不入提交。工程检查点不替代用户关闭里程碑。

文档归属、迁移和更新方式遵循 [维护规则](maintaining.md)。使用普通文档与 Git，不加载旧施工插件、任务派发模板、审查包或多轮代理流水线。旧实现、测试、fixtures 和历史通过结论不作为新交付。
