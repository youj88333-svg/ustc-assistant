## 1. 连开 13 周独立 Task 的完整 Burst

**目的：** 验证 13 周作业请求端到端地走真实的 create-task Burst：课程摘要定位有效范围、
单批 13 个独立 `create_task`、逐项遵循当前权限策略、最终 13 个独立 Task 且不触发预算错误。

**给 Agent 的消息（原句）：**

> 电磁场与波作业连续13周每周六截止，请根据这门课的有效周次分别创建独立Task。

**预期结果：**

- **首次查询**：Agent 恰好一次 `get_schedule(view=course_summary, query=电磁场与波)` 定位课程
  有效范围，而不是整学期 `events` 大范围读取。
- **模型行为**：若课程摘要对截止时刻或特殊周次是否包含存在未决细节，Agent 先发出**恰好一次**
  澄清；候选日期全部明确后，在**同一个工具调用组**里出现 **13 个**不同的 `create_task` 调用。
- **确认行为**：每个 `create_task` 仍按当前权限策略各自确认；取消其中任意一个**不会**回滚其余
  已确认项目。
- **最终状态**：13/13 全部批准并完成时 run 为 `completed`；12 成功 + 1 取消时 run 为
  `create_task_burst_partial` 并如实报告计数。
- **诊断**：不出现 `tool_call_budget_exceeded`；不出现隐藏的第二次 Burst；不出现
  TaskSeries/batch 工具或 schema。

## 2. 账号隔离

**目的：** 验证另一个账号看不到本次 Burst 创建的 Task 或调用记录。

**操作步骤：**

1. 用账号 A 完成 1 节所述请求。
2. 切换到账号 B（A 之外的另一个学校账号）。

**预期结果：**

- 账号 B 的任务中心不出现任何本次新建的 Task。
- 账号 B 的 Agent 诊断/工具调用记录不出现本次 13 个 `create_task` 的调用记录。
- 切回账号 A 后，A 的 13 个 Task 仍在且可正常查看。
