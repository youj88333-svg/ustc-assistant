## 1. 原关系语句（2026 春 电路/量子 二选一）

**目的：** 复测“2019 春”历史遗漏——两个历史课程重叠时，用户给出具体选择后应保存
`no_conflict`，而不是存成带 prose 的 `conflict`。

**给 Agent 的消息：**

> 找到 2026 春的“电路基本理论”和“量子物理 B”，把 2026 年 3 月 3 日那两节课记录为冲突，
> 我选择去量子物理 B。

**预期结果：**

- Agent 用有界的标题/日期查询定位这两个历史事件（不先整学期 `get_schedule` 长时间等待，
  也不无限“查引用”）。
- 给出具体选择后，关系以 `no_conflict` 保存（并存共存策略，不自动改出勤/听讲 overlay）。
- 确认卡只显示安全标题/时间，无 DB id / `ref_*`。
- 该 pairs 不再出现在冲突查询中；整段操作不依赖当前默认学期。

## 2. 课程内部 PlanBlock 显式 no_conflict

**目的：** 验证混合关系（课程 CalendarEvent 与 Task 的 PlanBlock 重叠）可从重叠 UI 分类。

**操作步骤：**

1. 在一节已有课程的时间段内安排一个 Task 的执行时间段（PlanBlock）并确认。
2. 打开对应周，通过重叠展开进入“处理重叠关系”。
3. 把课程与 PlanBlock 的关系保存为“不冲突”。

**预期结果：**

- 课程与 PlanBlock 重叠时默认都显示红色圆圈冲突警告，重叠展开可进入关系编辑器。
- 保存 `no_conflict` 后两者仍都可见，但冲突警告消失；冲突查询不再列出该 pair。
- PlanBlock 分类不提供“优先显示”前景单选（无伪造 series 身份）。

## 3. 六秒本地撤销提示（不遮挡聊天）

**目的：** 验证整日移动后的撤销提示是日程页本地浮动条，六秒消失，不盖住聊天。

**操作步骤：**

1. 在日程页对日期 A 执行整日移动（移动教务课程到 B）并确认。
2. 观察更新提示是否出现在日程页底部、是否离开日程页（切到聊天）后立即消失。
3. 大约 6 秒后确认提示自行消失；期间点击“撤销”恢复。

**预期结果：**

- 提示是 `schedule-undo-notice` 本地浮动条，**不是**全局 SnackBar，切页即消失。
- 大约恰好六秒后消失（无论是否已导航）。
- 六秒内点“撤销”一次恢复移动，恢复后提示消失。
- 提示从不出现在聊天页，不遮挡聊天输入。

## 4. Agent 整日移动的终态结果

**目的：** 复测确认后的 Agent 整日移动必须以成功终态结束，不再出现尾随 `grounding_failed`。

**给 Agent 的消息：**

> 把 A 这一天的所有教务课程移动到 B，其他日程不要动。

将消息中的 A、B 替换为第 0 节记录的真实日期。

**预期结果：**

- 点击确认后移动成功写入，聊天最终回复总结移动结果，**不以** `grounding_failed` 结尾，
  也无“请你重试”之类的伪失败话术。
- 非教务日历（考试、二课、个人事件、PlanBlock）不随之移动；若 A 当天没有某类数据，在
  记录中注明“无样本”。
- 取消时不移动且只能报告取消；源事件未被物理改写。
- 测试结束后清除该移动。

## 5. 重启后工具诊断重建与隐私

**目的：** 验证工具调用记录跨 App 重启后仍可展开诊断，且不暴露密钥/账号清单/原始引用。

**操作步骤：**

1. 让 Agent 执行一次包含读（如历史课表查询）与写（如建日程或关系）的完整对话。
2. 重启 App，回到同一账号，找到该轮对话并展开工具过程。

**预期结果：**

- 重启后该轮的工具过程仍能展开，显示工具名、次数、状态与错误码（与运行中形状一致）。
- 展开内容只含安全摘要，不含 API Key、账号名、内部 DB id、`ref_*` 原值或外部作业句柄。
- 账号乙看不到账号甲的任何工具诊断记录。

## 6. 学期 Task 请求先摘要再澄清

**目的：** 验证“这学期有哪些作业/任务”之类的请求用 `course_summary` 摘要，先问未决细节，
并保留可多次 `create_task` 的既有能力。

**给 Agent 的消息：**

> 这学期我有哪些课程作业要完成？

再根据其回答追问细节，例如：

> 给“电磁场与波每周六作业”建立任务，每周六截止。

**预期结果：**

- Agent 先尝试 `course_summary`（或窄范围）读取，而不是先做整学期 `events` 大范围读取并
  长时间等待/失败（较大范围详细 `events` 请求应被 `schedule_summary_required` 引导回摘要）。
- 对未决的作业细节（标题、截止、频率）先向用户澄清，不再静默假设。
- 澄清后仍可多次 `create_task`（如多门课各建一个），批量能力不被破坏。
- 不依赖当前默认学期，无硬编码 semesterId 进入请求。
