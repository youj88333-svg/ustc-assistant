# M6.1–M6.4 数据、晨报与提醒集成

日期：2026-10-15。依据[任务单](../plan.md)、[批准](../acceptance.md)、[09 K-09](../../../architecture/09-contracts.md#k-09-晨报与本地提醒)、10–12 与工作流。主代理负责事务、协调器、组合根和最终验核；Luna/max 完成已定纯投影/公告、控件、适配及独立测试，原生与跨层边界另外复核。所有代理声明均由根实际检查后才作为证据。

## 最终实现

- schema15→16 只增提醒设置/覆盖、期望快照、原生映射及独立晨报缓存/票据表。所有来源导入、直接隐藏、本地写和 Agent 批量/撤销的事务尾部捕获完整去私密时间事实，提交后广播修订。源缺失不自动取消；用户隐藏、跳过、不参加或完成才取消。
- 纯投影合并同刻两槽、继承系列/本次/默认，按北京时间规划最近180天/512项。全天当天09:00；任务截止与时间块独立。定时/全天转换暂时继承可用默认，保留原覆盖以便改回；删除后可回收映射，隐藏后恢复仍用原映射。
- 提醒协调器在事务外对账完整七字段，能恢复 OS 成功但 C3 未接受的窗口。设置中可主动发送无业务内容的测试通知；它没有可写或可恢复的业务目标。正常退出等有效在途发布并保留 OS 计划；维护先清计划/历史并读回，再清 C3，失败保留原映射和屏障。
- 晨报用独立匿名 C2/模型客户端，首帧后展示当天事实，后台查询昨日教务/财务公告。整个查询60秒/20次真实请求（重定向/重试/直连均计数）、每来源5页、最多6篇摘录；不知道排序就不按旧日期提前宣称全覆盖。来源失败与空结果分开。
- 模型估算输入≤4000 token、输出上限600，无工具、主聊天、备注/正文、图片、账号或内部ID。流式结果写独立卡和短期缓存；前台准入立即作废交付并仅排空晨报客户端，最多等待本地2秒。取消还显式撤本地流订阅；不等远端生成完成。关键事实、开关、配置或世代变化拒绝旧提交；自动最多两次，手动再试主动触发。
- Agent页保留聊天画布，晨报卡有高度上限并折叠详细出处。“讨论”只预填可编辑请求，需用户发送。日程/任务/时间块使用同一两槽编辑器；设置是辅助分区。公开链接沿用现有受限主动打开方式，不新增 Agent 工具。

## 发现与修复

| 失败或复核发现 | 修正与证据 |
|---|---|
| 完整提醒快照调用无范围旧 snapshot，未包含任务时间块；补入后缺 task 身份导致 projection 拒绝 | 内部显式 includeAllBlocks，保留 parent task id/version 及状态；C3/投影测试覆盖，不改普通查询默认 |
| 晨报取得事实与领取票据两次事务之间可发生编辑 | 领取后重读与 ticket 摘要复验；模型只能接收票据对应事实，夹缝测试覆盖 |
| 开关变化使旧活动 ticket 不能结束，重新开启仍不能认领 | 切开关同事务撤销旧 ticket；新世代拒旧提交且可以重新认领 |
| 旧远提醒占满512，挤占新近提醒 | 对具体已知目标重新解析后驱逐被容量排除的旧项；未知查询不据此删除 |
| 过去提醒被当目标失效，冷启动/稍后点击丢失 | 过去时刻只排除新调度；未变对象/规则的已有展示项仍可定位，30天之后清除；改期/状态/删除照常拒绝 |
| 正常退出可能补偿取消刚接受的有效发布；系统开关重试使用旧缓存 | 退出等待有效在途；每次对账重读能力，初始化失败可重试 |
| 从未启用时维护会触发原生注册 | C3 无映射/发布证据且未启用时跳过原生初始化；正常启动也不注册 |
| 隐藏恢复回收过早导致原生ID改变 | 取消后仍存在的目标保留映射；对象删除、世代变化、关闭或长期过期才回收 |
| 单次例外与父系列的全天/定时类型不同，切到系列后仍显示单次控件 | C3 独立只读 shape 端口按目标/作用域给当前时间类型；编辑器复验并选正确默认/控件，真实内存C3及widget均覆盖 |
| 第一轮新晨报测试有日期、忙碌启动、fake stream/ticket 不符合真实契约 | 修正合成夹具；未削弱生产校验。缺本地流取消是实现问题，单独修正并验核 |
| 旧版本迁移夹具仅降 user_version，却保留新增M6表 | 各 rewind helper 先移除六张新表，未来版本拒绝用17，当前断言16；碰撞/回滚断言保留，生产不使用 IF NOT EXISTS 掩盖损坏 |
