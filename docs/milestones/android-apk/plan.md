## 1. 目标、基线与范围

目标是在同一Flutter工程内交付可日常使用、可保留资料升级的Android私有APK；在实际验证过的APK鸿蒙环境中使用同一包。Windows1.00作为保留基线，公共业务变更仍需Windows回归，不能以手机迁移为由改变既有数据或安全承诺。

- Agent默认页和日程页，任务属于日程；单一持续对话、compact/clear、热心学长风格、图片及本地语音、折叠的过程/出处/已完成审批、可撤销许可与仅建议模式。

- 本地安排、重复/例外、来源备注/出勤计划、颜色/教室优先、教学节次、冲突、全天栏、任务截止栏、时间块、移动/撤销及维护恢复。

### 本次不扩展

不做原生鸿蒙HAP、iOS、公共商店发布、云后端、推送服务器、双端同步或Windows资料搬家；不迁移DPAPI密文/浏览器会话。用户手机重新建立来源资料，Windows原资料保留。若要带走旧任务、备注或聊天，应另行批准受控资料导出/导入，不能直接复制整个数据库。

不增加后台打开学校网页、整夜常驻服务、自动报名/退选、任意浏览器操作、通用文件下载、自动截图或语音云上传。通知后台触发与学校后台采集是不同能力，前者纳入，后者不纳入。

## 3. 内部接口与必须保持的事实

以下是拟实施接口责任，新增类型名不是已存在API；A0/A1将最小字段冻结后才能委派实现。平台特殊字段只进能力投影，业务模型不随系统复制两套。

| 接口责任 | 拟定契约与失败语义 |
|---|---|
| 平台装配 | 返回目录所有权、浏览器、凭据保护、通知、语音/图片/受控文件实现及能力快照；启动不请求麦克风/通知许可、不联网、不解密无关秘密。单项能力缺少只影响对应入口，不让本地日程因语音/通知缺失无法启动 |
| 数据所有权 | 复用`AssetOwnership.isHeld/ensureHeld`，抽出数据库与目录安全操作的最小端口。Android一个app-private父根及子目录承载现有存储；正式业务权威仍为`jw.sqlite`，内部演示数据独立且不作为日程来源，不顺手合库/删表。取得所有权后才开库/WAL/SHM/诊断/分区登记；Windows现有两目录及锁行为保持 |
| 凭据 | 继续`protect/unprotect(bytes,purpose)`和机制版本。Keystore只持不可导出的密钥，C3持密文/算法版本/随机nonce等封套；学校与模型用途分开，保护或保存失败保留旧值。密钥失效只要求重新提供凭据，不删日程或降为明文，不另建SharedPreferences密码仓库 |
| 学校观察 | 保留既有固定观察/认证/采集端口及会话、文档、操作、generation/epoch关联；一个来源一个通道，所有来源作业仍经C2共享租约。导航、脚本、端点固定登记；JS返回只投影业务所需字段。不得把Android拦截请求当成可普遍读取所有响应正文的接口 |
| 清理/恢复 | 先撤许可并持久标记不可复用，再停止动作/销毁页面/按Profile清数据，最后记录实际完成。区分访问已撤销、SDK删除完成、仍待清理；API超时/进程死亡留恢复状态，旧分区不因账号存在或删除重试被重新认领。不声称法证级物理抹除，也不静默降低为共享默认Profile |
| 提醒 | C3业务与期望同事务，P在事务外登记/取消并反馈；沿用稳定逻辑键、两槽、来源/任务有效性和维护屏障。能力区分系统通知允许、精确能力、应用退出后能力、点击能力、队列信息来自SDK/本机镜像；不能把插件缓存称为OS队列独立证明 |
| 原生接收器 | 不初始化Agent/学校登录，不绕过目录锁另开业务库。只使用受C3修订约束的最小调度投影及撤销标记；Native持久化仅作为平台登记镜像，不成为第二业务权威。维护/重置要阻止旧镜像重建，点击回应用后按当前对象与epoch复验 |
| 图片与导出 | 用户选择→原生有界流/受控临时文件→现有去元数据与图像限额；取消/失败/结束清临时副本。日志经SAF创建文档，内容URI不当作普通绝对路径；不申请所有文件权限，不导出数据库、认证资料或原始声音 |
| 生命周期 | 明确活动可见/非交互/后台/进程结束。录音退后台停止；来源/模型在失去活动宿主时按本次策略取消或保留受控等待，不自动重放旧批准。进程重启先恢复所有权/维护/分区与实际提交回执，再允许新作业，不依赖dispose一定执行 |

默认设置保持源码规则：系统提醒、晨报、每日二课均不因迁移自行启用；用户授权后才运行。定时提醒默认第一槽提前30分钟、第二槽无；全天按既有日期时刻规则。手机是新设备，日常许可和隐私选择重新确认，不能把Windows保存的许可视为手机已有授权。

## 4. 平台选择与先行核验

### WebView

首选AndroidX WebKit多Profile与受控Kotlin桥，而非把整套宿主换成一个通用WebView Widget。检查`MULTI_PROFILE`后，在初次加载前绑定各来源/候选Profile；认证页、frame、弹窗、挑战和业务页按现有普通WebView规则处理，不恢复CAL或全协议拦截。

补充检索发现`WebStorageCompat.deleteBrowsingData(profile对应WebStorage, callback)`可对缓存、Cookie及JS可见存储执行删除并回调；它仍要求`DELETE_BROWSING_DATA`能力。计划将其与Profile销毁/撤销/恢复结合验证，不能只靠`deleteProfile=true`认定磁盘已清。`deleteProfile`对仍关联页面或已加载Profile也有限制，这些生命周期次序必须在A0/A2试出可重复方案。[数据删除API](https://developer.android.com/reference/androidx/webkit/WebStorageCompat) · [ProfileStore](https://developer.android.com/reference/androidx/webkit/ProfileStore)

若目标提供方缺能力，先给出具体限制与替代方案证据：可评估很小的独立宿主/进程或官方数据目录方案，但不默认扩成多进程框架、不改全局Cookie兜底。未达到原隔离/清理条件的来源保持不可用，本地能力继续；改变原设计承诺须先作为明确取舍交用户，不能在最终交付时才告知目标手机无法同步。

### 凭据与备份

默认采用Keystore AES-GCM，每次随机nonce并将用途绑定为关联数据，硬件保护程度按设备实际报告，不设每次生物认证才能自动同步的新增门槛。[Android Keystore](https://developer.android.com/privacy-and-security/keystore)

推荐手机首版所有应用私有资料不参加自动云备份和设备迁移，且不提供新业务备份按钮；通知镜像/凭据/会话/执行状态重点排除。配置Android11及以前的备份规则与12及以后的cloud/D2D规则，优先将关键状态放入no-backup存储。不能仅靠`allowBackup=false`承诺所有厂商D2D均被禁止。[Android12备份变化](https://developer.android.com/about/versions/12/behavior-changes-12)

这是首版的数据保留取舍：正常同签名升级保留，卸载/清应用数据不承诺恢复；不把排除备份称作“已有备份”。若用户需要备份或桌面数据搬家，应先修订本计划。

### 系统提醒

先评估`flutter_local_notifications`作为通知端口内的成熟实现，版本在A0按当前SDK实际解析后锁定；原生桥只补它缺失的修订/清理/能力证据，不直接复制插件私有缓存格式。[上游实现](https://github.com/MaikuB/flutter_local_notifications/tree/master/flutter_local_notifications)

Android13+通知许可和精确闹钟能力分开申请/反馈；首选用户授予的`SCHEDULE_EXACT_ALARM`路径，未授予时如实显示不能保证准点，不拿近似提醒冒充精确。SDK返回成功也不保证用户一定看见通知。[通知许可](https://developer.android.com/develop/ui/compose/notifications/notification-permission) · [精确闹钟变化](https://developer.android.com/about/versions/14/changes/schedule-exact-alarms)

| 运行状态 | 计划支持/明确边界 |
|---|---|
| 前台、后台、日常锁屏、普通离开应用 | 注册后由OS触发，不靠Dart Timer或常驻服务；按目标机实际投递测试 |
| 系统回收进程、从最近任务移除 | 与系统强制停止分开测，厂商差异单列；在实际验证范围内声明退出后提醒 |
| 设备重启/应用升级 | 从持久登记投影重建，用户首次解锁后完成正常恢复；不承诺重启尚未解锁前可访问凭据保护区或完整提醒 |
| 权限撤销/通知渠道关闭 | 能力重新读取、停止错误登记、展示待处理；重新允许后按当前期望对账，不重放已过期提醒 |
| 用户在系统“强制停止” | Android15会取消PendingIntent，重新打开后恢复；不绕过用户停止意图，不承诺此状态下继续提醒。[Android15说明](https://developer.android.com/about/versions/15/behavior-changes-all) |

### A1目录与启动实施契约

### A1凭据端口实施契约

依据本计划、07/09/11/12的C3与秘密边界和15工作流，先实现可独立验收的Keystore保护原语，再由Sol装配平台工厂；不能把原语通过写成A1整体完成。

- Dart沿用`JwCredentialProtector`与`ModelCredentialProtector`；Android机制固定`android-keystore-aes-gcm-v1`，Windows仍用原DPAPI。学校用途仅接受C3的`ustc-assistant/jw/login/v1:<jw-owner-32hex>:<64hex指纹>`，模型用途仅接受`ustc-model-key/v1/<jw-owner-32hex>`，两族使用不同非导出AES-256/GCM密钥。
- 私有MethodChannel为`ustc_assistant/credentials_v1`，仅`protect/unprotect`，参数严格为`purpose`及`data`二项。明文最多16KiB、封套最多64KiB、用途最多256字符；封套为版本1字节、12字节随机nonce和含16字节认证tag的密文。完整用途作为AAD，不返回Key、别名、明文日志或底层异常文字。
- `protect`才允许创建对应族密钥，每次由Keystore生成新nonce；`unprotect`缺失/失效密钥、坏版本、用途不符、坏tag均拒绝，不能为解密重建密钥、清业务或改写C3。原生处理使用后台串行队列；临时字节缓冲尽力归零，不承诺跨运行时副本绝对抹除。
- 固定失败码为`invalid_request/unavailable/protection_failed/invalid_credential`，Dart映射现有类型失败；方法缺失/平台缺失明确不可用。持久数据只有C3密文与Keystore原生密钥，不建SharedPreferences密码库或一般秘密存取接口。
- 本块允许新增Android凭据原语/其instrumentation、Dart适配/合成通道测试及根注册代码；Manifest、组合根和平台工厂仍由Sol单一写入。验收覆盖两族往返、用途/族隔离、随机nonce、坏封套/大小、密钥丢失后拒绝且不自动重建，以及异常映射/不记录秘密；全部只使用独立QA合成数据。

- 新增私有`ustc_assistant/files_v1`，仅`pickImages`（最多3张）与`saveDiagnosticLog`两项，不接受任意路径/URL或读写方法。图片由用户主动系统选择，优先系统照片选择器，缺少时使用限定图像的可打开文档选择；只消费本次返回的content URI，不持久授权、不索取媒体库/所有文件权限。原生工作线程逐项有界读取，不依赖外部SIZE分配：每项最多10MiB、总原图最多30MiB，先验PNG/JPEG/WebP与解码尺寸不超过1600万像素，再交Dart既有单帧、去元数据、1536长边/每张3MiB/总6MiB规范化。不写图片缓存；原生/Dart临时缓冲尽力清零，取消/失败/离页使旧结果不可接受。
- 日志由现有`DiagnosticsPort.exportRecent`生成封闭脱敏JSON（7天/1MiB日志上限继续有效），Dart核对封套与记录白名单后仅传给原生保存。原生再次限制UTF-8大小与固定封套，经`ACTION_CREATE_DOCUMENT`创建JSON、写入本次content URI；取消返回未保存，失败不显示成功，尽力删除本次不完整新文档。无通用下载、分享认证资产、数据库或图片入口；系统保存界面离开前台不重放Agent作业，返回后保留草稿。
- Sol单一修改主壳/Agent、组合/偏好初始化、Dart文件适配、Kotlin桥、MainActivity/Manifest/Gradle及QA脚本；Luna分别修改日历和任务/设置布局，文件互不重叠。自动检查仅合成/loopback/独立QA及临时内容提供方；验证不可信SIZE/超限/坏图/取消/旧回包、日志取消/写失败/脱敏，以及真实控件矩形/大字/键盘/返回。根执行analyze、全套Dart、相关Android原生/集成、Windows回归与普通QA APK/生产Manifest/lint；结果写records，实机选图/导出和触摸体验留待A7，模拟器不替代用户确认。

平台依据：[Android照片选择器](https://developer.android.com/training/data-storage/shared/photopicker)、[SAF创建文档](https://developer.android.com/training/data-storage/shared/documents-files)、[Flutter预测返回](https://docs.flutter.dev/platform-integration/android/predictive-back)。不增加GMS回移依赖；不支持照片选择器的设备继续用系统文档选择。
