## Windows 首轮失败与实际原因

新原生套件首次 Debug 构建成功，但两项测试均失败：周事件标题同时带起始时间，精确纯标题 finder 未命中；详情 ListView 延迟构建下方关系按钮，测试尚未滚动便断言按钮存在。根改为验证该 C3 引用对应事件中的标题，并在指定详情滚动区真实滚动到关系按钮。第二轮学校缺失记录的覆盖/关系与重开场景通过，个人场景因前一输入将全天开关滚出可点击范围而失败。根统一确保控件可见并等待布局，且将点击未命中提升为测试失败，未忽略命中警告。继续完整复验，不把测试修正直接记成产品或原生通过。

下一轮已推进到预期 staleReference，原生 runAsync 测试桥却把该错误交给 Flutter 框架，外层 throwsA 得到未初始化结果而失败。根在桥内捕获并在外层按原堆栈重新抛出，恢复真实错误断言；此后两组新原生场景均通过。根查看仅由测试 RepaintBoundary 生成的日/周、个人全天跨日及来源详情图片，未读取用户屏幕。

收口复核另发现实际编辑缺口：每周系列转单次后保留 ordinal 0 的替代内容，原“编辑安排”只改系列原稿，当前显示内容仍被替代覆盖。C3 详情现明确提供替代标志；该情况的主编辑修改当前内容，另有“设置重复”入口保留原始重复配置和后续例外。根增加独立 Widget 反例及原生转单次后再次编辑/恢复再转回每周的实际场景，继续复验；不删除原例外来掩盖问题。
