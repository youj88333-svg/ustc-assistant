## 装配、失败与修正

Sol 单写 C0 任务/块/撤销类型、C3 schema 8→9 与单槽逆操作、关系端点版本守卫、一致投影及 C5 双端口控制器/正式组合根。任务与块共用 Task 聚合版本；删除父任务仅改变父标记，不改子块的已删除或人工状态。Undo 只由 C3 生成固定业务字段 before 和 post 守卫，恢复前复验上下文、24 小时期限、原始聚合及必要关系；只补偿原命令字段，版本继续递增，业务、槽、回执和安全审计同事务。来源导入不生成或替换本地撤销。

按已定接口派 Luna / max 实现任务页/表单、日程块入口与相关 Widget 场景，另一份独立文件承接 Task 存储反例；交回后再分别委派双端口迟到读/互斥场景、旧个人/覆盖/关系的撤销反例。文件归属固定，共享 C0/C3/控制器由 Sol 处理；子代理不运行共享 SDK 或 Git 写操作。根复读并串行执行检查，不采用子代理的静态完成声明放行。

首轮 analyze 的新枚举缺项、既有 Fake 的密封 intent switch、nullable/lint 和异步 context 守卫已修正。首轮 Task/日程存储 20 项通过、4 项旧场景失败：旧迁移断言仍为 schema 8/旧 epoch 增量，关系写后复用旧端点引用；根按新守卫从当前投影取引用并更新迁移映射，不放松生产版本检查。相关回归随后通过。

Task Widget 首轮两项失败为预期状态文案未跟随界面、故障注入晚于点击提交；根修正断言和故障时序。根还检查到任务页刷新后会重选旧引用，改为同 context 的当前列表引用，不跨 epoch 换绑；异步写反馈捕获原世代。首次全量为 703 项通过、1 项已有平台跳过，后续增加迁移/撤销/双端口反例，不能把该轮计数当最终数量。

schema 8→9 专用场景最初误用不存在的学术详情 encode 方法而加载失败；修正为闭合 toMap 编码后，旧回执新增 NULL 列使全行等价断言失败。根改为明确比较旧字段并额外断言新列全为 NULL，不伪造旧 Undo；两项临时原生 SQLite 保留/后半程失败回滚检查通过。数据为自建合成，未读正式记录或真实凭据。

新增撤销场景首轮 3 项通过、1 项失败：测试在维护仍进行时误预期 staleReference，现明确此时返回 maintenance，结束维护后旧 epoch 返回 staleReference，新 context 的旧槽返回 undoUnavailable。根保留三个阶段的拒绝断言；原始业务/槽/回执/审计回滚与重放计数不削弱。

Windows 首轮新增任务完整链路和两项既有日程场景通过，学校覆盖场景在版本断言失败：关系写已推进学校版本，后续覆盖/隐藏的旧固定计数少算一次。根修正版本预期，不忽略实际写/重开/缺失事实；完整套件再执行。根查看自有 RepaintBoundary 的任务/周画布，修正优先级文字重复、块状态标记挤占名称；完整状态仍在悬停和详情。明确打开关联任务时包含已完成/取消项，不受此前未完成筛选遮蔽。
