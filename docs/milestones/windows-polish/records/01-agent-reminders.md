# Agent管理提醒：实施与检查

日期：2026-10-15。用户要求“因为增加了通知功能，请增加与之配套的agent工具与其他相关”。范围、接口及验收在[同阶段任务单末节](../plan.md#接续扩充agent管理提醒2026-10-15)，现行规则见[09 K-08/K-09](../../../architecture/09-contracts.md)。这是Windows收尾的新增授权，不重开已关闭M6，不把旧阶段排除工具改写成当时已有能力。

## 实施与职责

- 完整应用配置增加只读`query_reminders`，共20个固定工具。无目标读默认两槽、系统提醒/晨报开关、隐私显示及当前本应用对账状态；有目标沿用会话短引用，读有效规则、默认/系列/本次继承、所选实例是否具备提醒条件及仍有效的已登记槽位。系统状态未知保持未知，不触发平台初始化或发布。
- 既有`propose_local_changes`扩充`set_reminders`和`set_notification_preferences`。定时/全天各遵循M6固定两槽契约，支持关闭或恢复继承；仅个人日程可改整组。默认、全局开关、通知隐私和晨报开关都是显式字段，省略保持原值，修改规则不暗中启用通知。新建安排、时间块或有截止任务仍沿用既有默认；需单独规则时取得新对象引用后继续处理。
- C3把提醒修订纳入签发提案及指纹，复验目标/上下文/维护/停止和授权；混合业务与提醒同事务保存、审计及回执，整批只捕获一次期望提醒。规则变更纳入共享最近撤销槽；撤销同时守卫目标和提醒修订，不能盖掉之后的手工设置。schema16不变，旧业务、对话、许可和秘密资产不迁移/清理。
- 新增目标提醒、系统默认/显示、晨报三类许可，与旧22类共25类；旧17类日常包不扩大。“以后不再确认”按实际类别记录并可撤销，仅建议模式和已撤销运行不提交。晨报启用卡包含公开联网、今日基本日程发往已同意模型服务及用量说明，通知显示说明锁屏含义。
- Windows仍由既有协调器在事务外登记/撤销，Agent不能任意推送或改系统全局权限。模型回执明确规则已保存、平台异步登记；读取当前已登记槽位需重新匹配当前期望的时间/内容摘要，过期映射不能冒充当前登记。没有原生ID/激活token或私人备注进入工具结果。
- 提示词升至`ustc-student-agent-v9`、工具协议升至`agent-tools-v5`；回复沿用共同的学长风格，按日常意思解释提醒，不以内部字段作正文。步骤中文标签、持久交互白名单、诊断工具枚举和运行帮助同步。未装配提醒端口的配置不暴露该变更形状或说明，完整生产配置不按问题裁工具。

Sol负责契约、关键实现、装配和根验核。Luna/max完成只读核对、独立纯规则映射和两个独立合成测试文件；根实际运行其检查，未采用子代理自报作为通过证据。Astra/high独立只读复核事务/权限/撤销，指出下述最终时间类型缺陷；根修复并补反例。全部工作限定当前工作区，未读取正式业务记录、认证资产或实际秘密。

## 问题及修复

1. 初版混合批次把定时日程改为全天时，规则仍按修改前形状验证，可能拒绝合法的新全天规则；若先设置定时规则再改全天，也可能提交后悄悄回退默认。现改为按完整业务批次的最终时间类型验证，业务先应用、规则随后应用且仍同事务，保留单次替换本身的类型。测试覆盖两种输入顺序与不兼容规则零提交。
2. 初次静态检查发现新增测试使用了错误的接口方法/启动入口及两个花括号提示，已按实际端口修正。新增行为测试还曾用撤销前的旧引用读取，以及把提交时守卫误断言在prepare阶段；已改为取得当前引用并核对实际提交拒绝，保留原版本守卫。
3. 首轮全套出现两项上下文回归：未装配提醒的合成配置仍带新增规则schema/说明，额外占用上下文并意外触发压缩。现按固定配置有无提醒端口装配对应变更，不按问句裁工具、不放大生产预算；两个原回归通过。另以真实完整20工具的schema/提示词做预算检查，低于默认12000 token软压缩门槛，给实际对话保留空间。
