## 接口与不变量

- C5只消费现有 `MorningRuntimeView` / `MorningFacts` / `MorningSummary`。摘要保持既有分段存储，允许受限Markdown；只读、安全链接和图片处理与聊天相同，不让Markdown自动联网。来源未知不等于没有公告，部分覆盖保持应用生成的事实版，不增加模型请求或自动重生成旧缓存。
- 今日重点由已有事实决定：冲突、今日截止、逾期、下个计划参加的安排。跳过/不参加/完成状态准确译为中文，不能把所有课程都视作仍需参加；覆盖诊断按需展开。
- `ReminderPairControls` 的 `pair/allDay/enabled/onChanged/keyPrefix` 及两个固定槽位保持；修布局不改变提前分钟数、日期时刻、全局继承、保存事务、OS调度与撤销。只改局部表单，不为修此处改全局主题。
- Agent提示词升版，交流风格与执行规则分别维护。现有19工具、北京时间和跨轮指代、当前事实/历史结果、私人读取策略、仅建议模式、许可/确认和committed回执行为保留。工具结果按用户目标选择信息，旧回复风格不成为后续模板；不改写聊天历史，不要求用户清会话。
- 学长是风格设定，仍是AI校园助手。明确请求继续推进到查询/具体方案/已获许可的实际动作；温和语气不能替代执行，也不替用户决定出勤或绕开许可。真实模型语气的效果与离线契约检查分开，不用词语断言证明模型已改善。

## 验收

1. 合成桌面/窄屏/放大文字下晨报重点易扫读、完整摘要可读、明细/来源可展开；隐藏/恢复/跨日、实时更新、失败重试和受控外链继续可用。无raw状态码或重复的空公告段落。
2. 两槽定时/全天字段标签与控件实际矩形不重叠；文字放大或窗口收窄不溢出，可改变第一/第二槽、选时、保存和恢复默认。禁用/失败不假报保存。
3. 以合成对话核查Markdown的标题/重点/列表可读、原始HTML/URL/图片不会自动执行/联网，工具与操作详情仍默认折叠；完整行为回归保证指代、许可和提交回执不退化。
4. 提示词测试覆盖不同工具清单/读取与建议策略；保留合成“选中这节课”“查下午安排”“修改出勤”“服务失败”等语气评判样例。未运行真实模型不能宣称真人语气通过。
5. 根执行analyze、全套test、相关Windows集成和默认入口Release；只用合成/loopback/临时资产。视觉用合成样例核对，生成预览留在忽略的build目录。用户只需核对修订体验，阶段不由自动结果自行关闭。

## 接续修订：按日常含义交流（2026-10-15）

用户反馈晨报仍像AI，聊天也把个人打算复述成“标为跳过”，仅问候时会重报旧日程和给操作菜单；授权继续修复，不需再审方案。现行07/09 K-07–K-09/10–15及以上保留条件继续有效。

- 聊天与晨报从同一份短人格/语义指导生成请求；人格不只是一句“学长”，而是围绕当前意图说人话。内部字段仍精确用于计算和执行，面向用户解释其生活含义；需要排错或用户问界面状态时可准确讲字段，不做硬禁词、字符串替换或输出词面拦截。
- `attendance`的不参加是个人计划，不能说成没课、学校取消或实际已经缺勤；完成一段学习安排不等于完成整个任务，自学不等于已经学完。普通问候按普通聊天承接，不主动翻旧资料或猜用户要改安排；不通过关键词裁剪19工具，也不丢弃历史。
- 晨报请求把既有状态投影为准确的日常含义，保留类型区别、未知和完整性门；无模型时的事实短报同步改写。原业务状态、摘要分段、缓存、票据、秘密/出站字段、4000输入估算/600输出及不完整公告处理不变；不擅自重发真实模型或改写旧模型缓存。
- Sol负责共享指导、两条请求装配、事实短报及集成；Luna/max只读核对状态语义和关键反例。新增合成检查覆盖同一人格确实进入两条请求、课程不参加/个人略过/时间块完成的区别、结构化JSON仍由宿主解析、部分来源失败不出现空公告断言。根复验相关与全套测试、相关Windows和Release；记录实际失败与尚未观察的真实语气，不把fake模型回复当生成质量证明。

## 接续扩充：Agent管理提醒（2026-10-15）

用户要求“因为增加了通知功能，请增加与之配套的agent工具与其他相关”。这取代本任务单先前不扩工具的本切范围；M6当期排除通知工具的历史不改写。依据为07、09 K-08/K-09、10–12的提醒/Agent条款、13 V-05/V-06/V-08、14审查方法与15工作流；复用M6已批准规则，不增加任意推送、脚本、URL或Windows全局设置操作。

- 新增固定只读工具`query_reminders`，不带目标读取默认规则、开关及本应用通知队列状态；可用已有`event_ref`或`task_ref`读取对应目标两槽有效规则、继承来源、是否有可用时刻/是否因个人状态暂停及当前已登记槽位。仅个人日程可指定`scope=series`，其余为本次/任务截止。短引用由既有当前对象解析，不暴露原生通知ID、激活token、账号或私人备注。
- 扩充既有`propose_local_changes`的`set_reminders`与`set_notification_preferences`。前者以`event_ref`/`task_ref`且仅一种确定目标，`scope=occurrence/series`，给`reminders`固定两项或`inherit=true`恢复继承；定时规则为`kind=before,minutes_before=0..10080`，全天为`kind=dayTime,day_offset=-7..7,time=HH:mm`，关闭槽为`kind=none`。后者可改`enabled/private_display/morning_enabled/timed/all_day_reminders`，省略保持原值；提醒规则本身不暗中开启全局提醒。
- C3沿用提案、应用确认/记住许可、同事务审计/幂等回执及共享最近撤销槽。新增提醒、系统默认/显示、晨报三种单独许可，旧22类许可和17类日常包不自动扩大。仅建议硬模式不提交，模型不能自批。晨报开启卡说明公开联网/模型用量与既有同意，显示详情卡说明锁屏可见性。
- 提案绑定当前提醒修订与目标版本；等待期间人工改规则、改期、维护或停止后拒绝过期提交。撤销同样校验提醒修订，不覆盖后续手工修改。原schema16与正式资料保留，期望提醒同事务更新，Windows登记/撤销仍由已有协调器异步执行。回执只证明规则保存，查询分别说明系统能力、登记数和失败，不能保证通知必达。
- Sol负责跨层契约、C3事务/撤销、工具装配、提示词、诊断白名单及根验收；Luna/max承接只读风险核查和独立纯规则映射/合成测试。文件不重叠才并行。检查覆盖定时/全天/个人系列与单次继承、任务截止/无截止、全局禁用/系统失败、确认/记住/撤销、过期/取消/回滚、原工具与数据保留。根完成analyze、全套test、相关Windows临时身份集成和正式Release；不调用真实学校/模型或生产通知进行自动测试。

## 接续修复：来源场次退出有效日程（2026-10-15）

用户举例教务调休与二课取消后旧场次残留，并在明确“完整本次学期/日期范围内缺失才停用、范围外及正常历史课表保留”后授权修复。本节替代09 K-05原“缺失继续作为有效安排”的产品规则；仅改变应用的有效投影，不宣称学校已取消或二课独立报名状态已核验。依据07、09 K-05/K-06/K-08/K-09、10–12、13 V-04/V-05/V-06/V-08与15，来源细节以JW/Young契约为准。

- C3以独立持久`source_retired`保存来源场次失效，与本次`presence`、用户hidden/出勤/备注分别存储。只有同一完整课表学期内未返回的旧课程，或完整Young所选日期内未返回/已无活动关联的旧日程，才设失效；范围外、失败、取消与未获完整性的响应不修改失效事实。考试无可靠完整覆盖，保持原边界，不因空考试集停用。再次收到同稳定键的有效记录可恢复，并保留本地身份、备注、隐藏、出勤与提醒覆盖；不猜测把旧日期的备注搬给新场次。
