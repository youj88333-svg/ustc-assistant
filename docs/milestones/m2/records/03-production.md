#### M2.3 正式查询与活动关联日程规格（2026-10-11）

设计依据由 `docs/README.md` 导航：07 只读/单账号/连续性及普通 WebView 边界，08 C1/C2/C3/C5 职责与一源一通道，09 K-01–06 及已批准活动关联语义，10 作业/封存/收口/认领与恢复，11 日程/查询安全投影，12 凭据与分区职责，13 V-01/02/03/05，以及本文件工作流和 M2 验收矩阵。应用内真实候选两项通过是本切输入；未验证的独立报名状态不加回范围。

- **C3 及连续性**：在现有正式 `jw.sqlite`、同一 JwStore 实例/事务队列内从 v1/v2/v3 增量升级 v4，只新增 Young 表。jw_account 继续作为唯一账号权威，既有 owner、JW 表/ID/overlay、回执、密码和目录原样保留。新增不可序列化 Young ticket，C3 自取已绑定预期账号；无账号时允许本次预期输入，完整查询或日程成功事务首次绑定，输入不能改换已绑定账号。Young 独立 generation/job/permit/receipt/event/overlay，使用共享 owner/resetEpoch，不取得 JW 凭据或变动 JW 许可。
- **C1 封存及 C2 顺序**：复用已经实证的固定 reader，前后服务端 username 匹配 C3 ticket，完成全页/全日期并最后复验 session/document/operation 后封存；包含原 ticket stamp、具体分区、契约、采集文档、完整日期覆盖和不可变必要业务字段。正常关闭不撤销产物，取消/维护仍由 C3 原 generation/epoch 和 job 状态拒旧提交。共享租约从开始、用户登录暂停、读取、真排空、提交到认领/交付结束；失败保持恢复和租约，不用候选摘要布尔值或任意 digest 授权。
- **独立查询**：固定活动列表读取所有页，成功由 C3 复验并提交独立查询计数回执和 Young 分区许可；活动列表只在内存交付名称、活动时间、地点和独立报名时段，不进入日程或活动持久事实表。列表内已实证必要信息可本地展开，不添加未验证详情 endpoint。新查询/取消/失败/清分区清除未交付列表；认领完成、原作业仍可交付且未被取消才显示。提交后的许可保留，后续取消不伪报已无提交。
- **日程导入**：日历 id 为稳定外部键，itemId 为关联属性；先检查所有行/页及跨日 ID 一致性，再排除未关联。保留 title/place、UTC 起止、关联属性、presence/version，完全相同跨日记录合并，同 ID 内容/关联冲突拒绝。选定范围为北京时间首日零时至末日次日零时，最多62天，按区间相交检查覆盖。范围内缺失仅标 missingWithinScope；范围外保留且不推断撤回，缺失不自动隐藏。再次出现/内容更新保留 localId/hidden，隐藏命令显式 Young 来源、版本、账号/epoch 和持久回执。成功范围与导入回执同事务保存，初始 UI 默认北京时间当月，可在同步开始前选择。
- **平台与产品**：Young 专用 `young_partitions_v1`、yp ID/Young attempt/ref/permit，不与 JW 或未认领观测分区互换。启动串行调和；成功许可认领可恢复、无许可清理、确证串号只撤销 Young 许可，身份未知/冲突保留已认领分区。清二课登录资料不影响 JW 数据/密码/目录/许可或二课日程。正式同步/查询共用一份 Young C2，固定业务页自动导航和读取，学校登录/验证码仍由用户完成；本切不读取观测手填秘密，也不复用 JW 密码，不声称已经装配 Young 自动认证。
- **分工/文件**：Sol / max 负责 C3 v4/ticket/事务、现有 reader 的正式封存接续、C2/组合根与最终检查；Luna / max 限定新 Young 作业/数据/采集模型或独立分区实现，另一 Luna / max 限定冻结 port 的面板及行为测试，文件不重叠才并行；Astra / high 按需复核实际跨层实现。仅修改本 app/ 与当前文档，SDK 检查由根串行执行，所有自动测试合成/loopback/临时库。
- **完成条件**：三条旧版本升级路径和既有 JW 事实保留；首次绑定/错账号/旧票/取消提交/保护或 SQL 失败与重放；查询不写日程、未交付取消丢弃；日程重复/更新/缺失/范围外/隐藏恢复；独立分区复用/真排空/认领恢复/清理及共享互斥取得自动证据。根 analyze/test/相关 Windows/build 后交新版；用户验证真实列表必要信息、首次日程/时间/名称、重启再次同步、隐藏恢复/JW连续性及取消/清二课资料。真实结果分别记录，未批准后补项仍开放，不能仅由实现或合成通过关闭 M2。

本轮失败与修复保留：

- Astra 发现前序 JW 恢复占租约时 Young 延后初始化却被当作已初始化，未 ready 的 registry 阻止正常退出。根加入显式初始化状态：准入前必须调和；退出先完成观测/JW 收口，再持同一租约补 Young 调和，仍失败则保留恢复与目录所有权。延期不授予正常打开权限。
- Astra 发现查询提交后认领失败仍保存待交付列表，重试恢复会重新显示失败作业的旧结果。根在失败时清除未交付产物，保留已经提交的回执和具体许可，恢复只重试认领/清理。提交后取消只撤销原 generation 的交付资格，不回滚成功回执。
- 首次 analyze 报告 57 项：根草稿缺少分支花括号，以及 UI 测试引用、测试可空密文类型和少量样式问题；按限定文件修复，不放宽生产守卫。首次四文件局部测试为 23 通过、21 失败；C3 使用 `n` 别名而既有计数助手读取 `count`，导致读 view 失败，已统一；采集测试把合法的两条/一页误期待拒绝，改为真实多余页反例；UI 测试多处未滚动到按钮，修复测试点击与剪贴板调用过滤。后续三文件为 31 通过/1 失败，剩余是包含嵌套 List 的 Dart record 比较按引用导致同值误判；改为可深层比较的列表，单独 C3 16 项实际通过。完整最终结果另列，不把中途失败改写为通过。

新增原生合成正式链路验证只使用 loopback、临时库和新分区，覆盖完整查询不写日程、关联过滤、重复/缺失/范围外/重现、隐藏/重启/清二课资料、旧 attempt 合法复用、取消及身份冲突/确证串号。检查不访问学校、正式数据库或会话资产；既有 JW 事实连续性由合成升级和隔离回归验证，真人仍待新版验收。

#### M2.3 真实失败与自动认证接续（2026-10-11）

用户实际启动新版、查询活动并本人登录后，点击继续，学校窗口退出；摘要 idle/activities、accountBound=true、profileRetained=false/profileReused=false、committed=false、staleResult，normalization=null、二课本地/导入/查询计数均零。保留为首次正式真实失败，不改写为通过。当前证据限定失败发生在正式封存返回之前，不是已提交后的认领失败；尚不足唯一确定真实 stale 分支。根与 Astra 在现行代码定位页面完成不等于 SPA 路由稳定的时序缺口，先用闭合阶段诊断及合成延迟主路由回归定位修复，不降低文档守卫或自动重试已发出的学校业务读取。

用户要求二课同 M1 的完全自动化，随后明确两个账号完全相同、大部分逻辑复用。本决定扩展此前仅人工 Young 认证的切片：教务和二课共用唯一学校账号及现有受保护凭据，由来源作业向 C3 申请一次性秘密租约，分别投递当前确切学校 CAS 表单；不复制两份密码、另建秘密存储或混用浏览器登录资料。历史 JW 命名的保护 purpose/表名保留以兼容已存密文，只扩展授权的同账号固定认证用途。学校业务身份仍各自核验，验证码/通行密钥/额外授权仍由用户完成，手填秘密不读取。此用户指令替代早期“不复用 JW 密码”的 Young 准备范围。

本切实现与复核续记：

- Sol 提取不持有秘密的 `SchoolAuthenticationDriver`，JW/Young 共用单次 CAS 状态驱动，保留两来源独立票据与当前文档端口。Luna / max 限定实现正式面板/闭合 DTO、共享 C3 与 C2 行为测试、原生合成夹具；根审查集成并实际运行全部 SDK。Astra / high 只读审查原 stale 时序与新认证/读取交接，未以审查声明代替验收。
