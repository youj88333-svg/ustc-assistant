正式用户通过未来 Agent 使用这些搜索、读取与知识库能力，M3 不新增独立搜索页、校园资讯页或知识库浏览入口。M3 交付与模型及界面无关的内部接口和证据结果，不生成问答、摘要、选词或工具调用循环；后续 C4 再定义模型可见工具、参数映射、授权与安全结果投影，C5 承担对话及引用展示。M3 不预注册工具、不建立模型 Schema/提示词或调用模型，不需要模型 Key、向量库或云端 OCR。

临时验收界面可以提供查询、翻页、正文/片段与原文定位预览，以及受控维护操作；只调用同一内部接口，不承载查询/分页/排序或更新规则，不绕过 C2/C3。入口标明验证用途并与正式用户路由隔离，后续移除不影响核心能力和自动契约测试。本期不以独立产品界面或真实 Agent 对话作为关闭条件。

### 边界结论与仍待验证的事项

本期建立三类内部能力：在线查询课程与公开点评、在线检索/读取指定校园栏目及文章、本地检索/读取精选长期资料；由后续 Agent 选择调用并向用户交付信息。只有第三类持久保存全文，前两类只用有界会话缓存。知识库不生成政策答案或课程建议，也不从通知创建日程/任务。在线校园能力以有界栏目条目和正文读取为必达范围，原生关键词查询需独立契约证据，不把未验证的财务搜索或全站检索列为既成能力；结果须让后续调用方知道实际可用能力及覆盖限制。

现有栏目、详情、PDF 和图示观察已足以确定这些边界，无需为此继续全站探索。启动实施前仍须锁定首批材料白名单（单篇或独立章节、适用人群/版本和排除段落），定稿可被未来工具适配的内部输入/输出，并验证正式客户端、中文索引、受限 Markdown 内容与临时预览、资源限额及版本载入。这些属于限定范围内的内容核对和工程验证；无法满足时保留失败，涉及缩减核心交付再交用户决定。

## 文本、质量与出处

每份入库材料保存完整规范化文本，并按标题/段落/表格/流程说明生成可定位片段。出处至少包括提供方、栏目/主题、稳定文档键、文章 URL、材料 URL、原始材料摘要、提取器版本、抓取与接受时间；发布、更新、规则适用期分别记录，未知就保留未知。PDF 物理页与正文印刷页分开，网页保留节名或元素定位；不以更新时间推断规定现行有效。

| 类型 | 提取和可用条件 |
|---|---|
| HTML 正文 | 排除导航/隐藏弹窗/脚本，保留段落、标题、列表和表格关联；图片/PDF 嵌入不是合法空正文 |
| PDF | 优先提取文本层，按页识别文本、图片和真正空白；保留多栏阅读顺序、表头/单位/合并单元格，不把全页机械拼成一行 |
| 图片/扫描页 | 开发时用 MinerU/OCR 辅助定位，难识别内容交 Luna / max 对照原图形成完整描述，Sol 校核；没有看清的内容列待核对，不猜补 |
| 流程图 | 开发时将角色、先后、分支与条件写成可读段落/步骤，由 Sol 对照原图校核；仅识别到词不能冒充完整流程，新图未经核验不替换已接受描述 |

材料制作状态区分候选、转换中、待校核和已核验；应用只接受满足质量条件的版本，并区分本地可用、更新待处理及读取失败。首批核心材料须逐份核对日期、金额/单位、材料要求及流程条件等实际内容，字符数不替代质量。不存在的 OCR 置信度字段不得编造。

### Markdown 与开发时转换

知识正文以受限 Markdown 为保存格式，支持标题、段落、列表、引用、表格和经过校验的出处链接；派生纯文本供中文检索，片段绑定原文节/页定位。禁用原始 HTML/脚本和自动图片联网，不把 Markdown 中的链接作为新抓取许可。Windows 与未来移动端共用内容格式及数据契约，移动端渲染与平台能力仍单独验收；本期 Windows 装配受限 Markdown 阅读与中文检索，真实验收状态见阶段记录。

MinerU 仅用于开发时的公开资料预处理，参考用户提供的 mineru-convert 技能（外部路径 `E:/dsh/data/skills/mineru-convert/SKILL.md`）及其 document-visual-reading 技能；先查缓存，转换后读取并对照原页。Luna / max 整理困难图示、表格和描述，Sol 实际校核，不将转换完成记为内容通过。只向该制作工具提交已选公开资料，不上传学校业务/会话/秘密，不修改工具全局配置，也不把 MinerU、Token、Python、PowerShell 或模型调用放进应用/安装包。

校核稿位于 knowledge/curated，作为可审查的只读资料版本输入，含来源材料摘要、转换版本及校核范围；应用导入后 C3 是当前材料/索引的唯一持久权威，源码资源不是另一份可写数据库。首批样稿不等于已核验整套目录。文件中的排版图片需转成必要文字或标明未覆盖，不能靠本地图片路径留存缺失内容。原文变化时由开发流程重新整理并发布新资料版本；本期不搭建内容服务器或运行时自动 OCR。

## 责任、接口与持久化

| 归属 | 本期责任 |
|---|---|
| C1 | 评课/校园各自的固定 HTTP、目录/条目/材料关联、响应与文本语义校验，产生不可变结果；不写库 |
| C2 | 所有在线查询及在线正文读取的唯一入口，与 JW/Young 共用全局来源租约；管理预算、取消、收口和交付；不负责本地知识库载入/读取 |
| P | 受控文件/临时资产、外部链接等实际所需能力；资料制作工具在应用之外运行，不为 M3 装配运行时 PDF/OCR/模型端口 |
| C3 | 公共本地上下文、材料文本/片段/索引、回执/审计及维护世代的唯一持久权威；增量升级保留既有事实 |
| C4 | 后续阶段适配已验证内部接口为 Agent 工具，管理授权、模型安全投影及对话；M3 不实施或注册工具，不直接访问适配器/库 |
| C5 | M3 临时验收入口及受控材料维护编排，投影字段/定位/状态，执行用户主动的原文链接委派；未来正式展示由 Agent 对话接入，无独立查询产品入口 |

概念端口为 searchCourses、readCourse、browseCampus、readCampusArticle、loadKnowledgeEdition 与 C3 的 searchKnowledge/readKnowledgeMaterial；它们是应用内部端口，不是已生成的 Agent 工具或对外服务。来源原生关键词查询仅在限定范围契约成立时启用，不承诺全站搜索，财务先保障栏目条目及本地全文检索。输入/结果的通用约束以 [09 K-07](../../architecture/09-contracts.md#k-07-公开文本材料与知识库)为权威；M3.1 定稿版本化 DTO/稳定错误、能力状态、有界分页与按引用读取，避免未来 C4 重做抓取/检索。入口接收固定范围/受控引用，不接受任意 URL、脚本、SQL 或文件路径。

### M3.1 内部接口 v1

版本标识为 public-query-v1 / knowledge-edition-v1，不是 Agent 工具 Schema；业务核心只用 Dart 值对象/端口，不引用 Widget 或模型 SDK。在线调用全部经同一 C2 协调器和既有 WorkLeasePool，本地检索/读取和载入经 C3；临时界面不能直接调 HTTP 或 SQL。

| browseCampus | 固定教务/财务栏目、可选关键词、每页 1–20 条和受控分页值 | 条目及受控文章引用；教务原生检索独立验证，财务关键词契约未成立时明确 unavailable，不能返回假空态 |
| readCampusArticle | 所选栏目签发的文章引用、节范围/文本预算、可选正文游标 | 所选公开正文、原文/附件链接与日期语义；游标绑定原引用、输入与快照，不丢超长单节尾部；PDF/图示正文未读取时报告覆盖限制 |

| loadKnowledgeEdition | 固定随包清单键及受控本地批次意图 | 逐材料事务回执，已提交/未提交/重放分别计数；只加载校核材料，无任意路径/URL，也不因查询自动载入 |
| clearKnowledge | 独立用户确认的本地维护意图 | epoch 先作废在途读取/载入，排空后清限定文本/索引/回执；保留 JW/Young 事实和密码，启动不自动重建 |

结果以类型化候选/正文/片段和 Evidence、Coverage 值对象表达：提供方、标题、原文/材料链接、观察/接受时间、可证日期、材料修订/质量、节/页定位；返回数量、当前范围、排除项、截断与是否可继续分开，不补造全站总数。引用/分页由能力层保管和复验，10 分钟有效、每来源最多 256 个，重启/维护后失效；引用中的显示 URL 不作为调用输入。

初始预算：在线 HTML 解压后每页最多 2 MiB、单作业最多 8 次跳转及 60 秒；在线正文或单次本地正文最多 12,000 字符，知识片段最多 400 字符；索引扫描只限首批目录，材料数上限 256、文本/派生片段合计 128 MiB。超过范围稳定拒绝/报告截断，不删除已接受材料。可用性/合法空结果与 invalidRequest、busy、consentRequired、cancelled、staleReference、unavailable、accessRestricted、campusOnly、networkFailed、sourceSchema、resourceLimit、storageFailed、closed 分开。具体来源参数在来源参考维护，不复制 URL 规则到界面。

SQLite 中文检索首版采用有界 Unicode 子串检索与标题/主题优先排序；不依赖未知 FTS 中文分词能力，不引入向量库。目录很小，但仍须测两字中文、多关键词、空态和扫描预算。资料维护采用单独批次，取消先作废未提交内容，已提交材料保留并报告；材料修订同时覆盖正文与校核定位，修正原件未变的文字也可更新。

公开网络作业使用 C3 产生的公共本地上下文，不伪造学校身份，不要求先绑定 JW/Young；原作业戳、来源 generation 和 reset epoch 继续复验。本地材料载入是 C3 受控命令，绑定操作身份、公共上下文、reset/知识库 epoch、目录版本及目标修订；不借来源网络许可或持有不存在的学校身份。来源候选引用在新读取作业中重新授权，不能沿用旧作业许可。

本地 search/read 不占 C2 来源租约，学校等待登录期间仍可查阅。loadKnowledgeEdition 由 C5 发起、C3 以受控本地操作串行受理；同一时刻一项知识库载入，可与来源网络作业并行，数据库提交仍按事务序列化。C5 管理该本地批次进度/取消，C3 复验操作有效性、知识库 epoch 和维护状态；清库使相关批次失效并排空已受理事务，完全重置排空两类作业。它不创建第二来源租约/伪造 source job。

Markdown、纯文本片段、可重建索引和元数据进入同一 C3 SQLite 管理范围。稳定文档键维持同一材料身份，校核修订涵盖 Markdown 正文/定位与校核版本；完全相同修订重放不重复写入。原件摘要与 MinerU 版本相同但校核稿修正，仍是新修订，不被旧去重挡住。按材料原子提交正文/片段/索引/当前修订及回执；有效新修订替换全文，仅留必要版本元数据。失败/取消保留旧版；批次已提交/未提交分别报告，取消后不笼统显示“无修改”。

只保存选定长期材料的 Markdown/文本与元数据，不保存检索历史、临时通知全文或原始二进制。应用若创建临时输入，P 先登记归属，完成/取消/失败后排空真清理，启动恢复遗留；制作工具的临时转换目录另行核对清理，不混为应用能力。清知识库递增独立 epoch 并排空相关作业，保留 JW/Young 日程、覆盖、学校密码与目录；清学校登录资料不清知识库。完全重置明确包含知识库及应用临时资产。清库后不自动从随包资料重建，重新载入需新的明确操作。

## 网络与资源验证

用户明确本机在校园网且使用 7897 代理：固定校园来源若返回明确的校内 IP 限制，可在同一受控客户端按本次授权用本机直连重试；不改全局代理、不转发学校秘密、不降低 TLS。直连与代理是请求路由选择，不增加浏览器/Python备用实现。实际登录限制仍跳过，普通 403/空页不直接判定为校内限制。财务旧链接的 HTTP 重定向与已核实 HTTPS 正文别名按具体契约处理，每次请求仍复验目标。

应用 M3.1 的起始验证预算为 HTML 2 MiB/页、知识库归属 Markdown/文本 128 MiB；请求页数、渲染大小、派生索引磁盘和查询耗时据实际构建测量定稿，达到限额暂停新增，不删除旧接受内容或其他业务。公开 PDF/图片制作遵守转换工具的文件/页数限额；已见约 29 MB/62 页、6 MB/38 页，先测页数再选择模式。制作工具预算不成为应用的原生 OCR/PDF 能力承诺。

本地索引必须验证“缓考”“缴费”等两字中文词和较长词，不能仅凭西文分词或三字索引宣称中文搜索成立。具体 SQLite 功能/分词和有界短词查询由 Sol 据实际 Windows 构建测量选择；索引可以重建，知识库正文不是派生缓存。财务浏览器原生搜索可用，但当前直接 HTTP 契约未成立，M3.1 继续核对；首版不承诺全站索引穷尽。栏目浏览和本地知识库查询独立可验，若线上关键词查询不可实现，明确保持该能力不可用，不静默用外部搜索或浏览器代替。

## 实施顺序、协作与文件归属

1. **M3.1 契约与资料制作**：Sol 定稿版本化内部查询/证据契约、两来源请求/分页/空态/条目引用、公共上下文和长期目录；恢复施工后用 MinerU 辅助及 Luna / max 整理困难材料，Sol 原页校核。验证中文检索、Markdown 内容、预算及代理/直连，不生成 Agent 工具。
2. **M3.2 评课内部闭环**：Sol 处理 HTTP、C2/C3 授权/世代和结构化交付；契约明确后 Luna / max 承接解析或临时验收界面，完成真实课程/学期/点评核对，核心逻辑不依赖界面。
3. **M3.3 校园检索与知识库内部闭环**：Sol 处理版本载入、公开持久化、增量迁移、事务和维护；Luna / max 承接已定栏目解析、文本映射或临时预览。两提供方共用公共基础，保留各自来源规则。
4. **M3.4 集成与验收**：Sol 独立复核内部调用场景、结构化证据及失败反例，按需请 Astra 复核接口复用/持久化边界；完成相关全套检查、受控公开契约与实际随包资料核验，临时界面是可选辅助，不强制用户重复点击。记录后续 C4 接入条件。

用户已批准恢复：完成接口与首批目录后按依赖实现。Sol 单一写入共享契约、C2/C3/数据库迁移、组合根和任务单；Luna / max 承接契约已定的公开解析、资料正文或临时界面，文件互不重叠才并行。修改限当前工作区的 app/、knowledge/、必要制作工具及文档；不直接检查正式业务记录/秘密，不操作其他 worktree，不推送；Sol 在相关检查通过的节点建立本地 commit，子代理不自行提交。每份派发列明现行 07–15、批准修订、接口/不变量、文件范围、依赖和行为验收；发现冲突交 Sol。

## M3 关闭条件

本阶段是内部能力，不要求用户执行公开查询、重复载入、重启和清库三组机械操作。公开来源由 Sol 使用正式客户端受控核对；固定首批资料由 Sol 对照原件校核，并在独立临时原生数据库中验实际随包版本。事务/维护/保留的故障边界用合成和原生临时证据证明，不直接读取用户正式数据。正式 Agent 的回答质量和使用体验在后续接入阶段验收；用户只需审阅阶段结论并决定是否关闭，不将取消人工操作记录为真人测试通过。
