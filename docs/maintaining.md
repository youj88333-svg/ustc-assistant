# 文档维护规则

本规则按用户 2026-10-11 的要求采用：M3 开始前整理现有资料，让不同阅读目的有明确归属。只调整信息组织，不改变产品范围、安全边界或验收结论。

## 参考与取舍

[Diátaxis](https://diataxis.fr/) 按学习、操作、查询和理解区分文档用途；本项目据此分开运行说明、来源参考和设计解释。[arc42](https://arc42.org/overview/) 分开架构视图、横切概念、决策、质量与风险；现有 07–14 的有效内容按这些职责归位，保留已有条款编号。

重要取舍采用 [Nygard ADR](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions) 的背景、决定、状态和后果，记录原因及替代关系。[arc42 的决策建议](https://docs.arc42.org/section-9/)要求避免重复已有说明，本项目只为已有的重要批准或新的重要取舍写独立记录，不补造用户批准或为每次修复写 ADR。

目录是本项目的适配方案，不声称照搬上述模板。继续使用 Markdown 和 Git，不引入文档网站、插件、生成流水线或新的运行依赖。

## 信息的唯一归属

| 内容 | 权威位置 | 其他文档如何使用 |
|---|---|---|
| 产品约束、模块职责、通用契约及运行链路 | `architecture/07–12` | 链接具体条款，说明本层的落实关系 |
| 重要批准、原因、后果与替代关系 | `decisions/` | 设计保存当前规则，决策保存为什么采用 |
| 单个来源的端点、字段、分页、时间和稳定键 | `reference/sources/` | 通用契约引用来源参考；阶段任务不另建永久契约副本 |
| V 项验收条件、当前证据范围与残余风险 | `quality/13-risks-and-acceptance.md` | 只更新当前登记，详细证明链接阶段记录或前置实验 |
| 设计审查方法和已发生的审核裁决 | `reviews/` | 记录审查时点，当前阶段状态另查状态页 |
| Sol/Luna/Astra 分工及施工方法 | `workflow.md` | AGENTS 保留执行要点并链接标准 |
| 一阶段的范围、未知项、接口、不变量和完成条件 | `milestones/<阶段>/plan.md` | 每阶段一份任务单，接续切片明确依赖 |
| 实施、失败、修复、实际命令和人工结果 | `milestones/<阶段>/records*` | 按切片归档，保留发生时状态，不复制到设计正文 |
| 用户关闭决定及未实证项 | `milestones/<阶段>/acceptance.md` | 状态页只给当前结论和链接 |
| 项目当前阶段与下一步 | `status.md` | README 只提供短导航，不积累进展流水 |
| 启动、使用、调试与检查命令 | `app/README.md`、`verification/README.md` | 不嵌入逐轮施工报告 |
| 整理前原文和旧设计 | `archive/` | 不参与默认施工上下文，保持只读 |

简短导航和状态摘要允许重复；详细规范、验收原话和检查记录只维护一个权威位置。记录中的旧规格用于追溯，当前实现应从设计和来源参考读取。

## 更新规则

1. 先判断改变的是规则、决定、实现记录还是验证状态，再写入相应位置。新规则与已批准边界冲突时由主代理处理，涉及范围、安全或保留取舍仍交用户决定。
2. 重要决定写明真实背景、状态、依据和后果；被替代的决定保留并指向替代项，不覆盖原批准。
3. 较大阶段先写 `plan.md`，再按可验收切片增加记录。一个记录包含多个无关主题或阅读负担明显增大时按主题拆分，并保留索引。
4. 自动检查、真实人工验收、批准与尚未观察分开记录。阶段关闭不自动关闭整体 V 项；没有新摘要时不推断新的回执和数据计数。
5. 首次关闭写 `acceptance.md`，保留用户原话及范围；后续发现问题或补验追加新条目，不把失败改写为通过。
6. 入口、AGENTS 和运行帮助只保留当前有效状态。阶段历史留在记录；原文进入冻结档案后不再追加。
7. 文件迁移更新仓库内的有效相对链接；旧路径保留简短迁移说明和被引用的锚点，不保留另一份现行正文。

## 检查与阅读

整理或修改文档后，从仓库根运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-docs.ps1
git diff --check
```

文档检查覆盖当前本地链接、标题锚点、迁移入口、knowledge 下的制作文稿及归档内容的 SHA-256。上述执行策略参数仅用于本次检查进程，不修改系统配置；旧档案中的历史出站链接不作为当前有效性承诺。纯文档整理不运行学校采集、不读取业务库或认证资料，也不重跑没有代码变更的 Flutter 测试。

本次迁移依据和核验见 [整理记录](reviews/2026-10-11-document-reorganization.md)。后续阶段由主代理按设计先明确范围和验收条件，再维护对应任务单，不从旧里程碑编号推断新阶段范围；阶段状态只在状态页及阶段索引更新。
