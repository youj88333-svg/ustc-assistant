# 07 产品约束与本分支决策

## 本分支当前规则

2026-10-09 用户批准[首轮审核](../reviews/2026-10-09-design-review.md)的修订建议，随后批准首版安全边界调整与本地 M0 分段准入。以下是 `codex/design-reset` 的有效规则；M0/M1/M2 当前交付与剩余范围见 [状态页](../status.md)，整体设计尚未冻结。历史设计完整保存在 [档案](../archive/README.md)，不提供本分支的授权或通过证据。

### 产品范围与不变量

- 保留教务课程和考试、[二课个人日历中的活动关联日程](../reference/sources/young.md)、二课报名活动只读查询、评课、校园公开信息五条来源，以及本地日程、Task、PlanBlock、冲突解释、出勤和听讲记录、提醒、撤销、历史与 Agent。二课活动关联不作为独立的本人报名成功或取消证明。
- 本地优先；单账号；Windows 优先，Android、iOS 后续。更换学校账号经用户确认的完全重置，不提供多账号并存切换。
- 二课每日同步是设置中的独立授权，默认关闭；显式启用后仅在运行中的应用前台空闲时，按北京时间 06:00 后同步昨天起 31 天的活动关联个人日历。复用现有只读来源与已保存学校凭据，不调用模型、不新增 Agent 工具，也不创建退出后的后台进程；正常启动和本地日程读取不等待网络。调度与撤销细节见 [09 K-04](09-contracts.md#k-04-作业凭据与交接)和 [10 运行链路](10-runtime.md#二课每日自动同步)。
- 学校记录按稳定外部身份更新，本地身份与 UserOverlay 连续保留。同步不得物理删除学校记录；`source_retired` 与 `presence`、用户隐藏/出勤/备注等覆盖分别保存，不改写用户决定。
- 只有来源契约证明本次选定范围完整时，范围内不再返回的适用课程或活动关联日程才可记为 `source_retired`。范围外、失败、取消和不完整响应不改变该位；考试没有可靠的完整覆盖，不从空考试集推断失效。范围外观察不能让既有失效记录复活。
- 默认日历、Agent 当前日程、规划、冲突、晨报和提醒排除 `source_retired`。用户显式查看历史时可读并标注“来源已不再返回”；这不证明学校取消或本人报名状态。相同稳定键按来源适用条件重新返回才恢复来源有效性并保留本地身份与覆盖；改日期形成的新键不迁移旧备注。正常的旧学期课程仍按原日期显示。
- 窗口之外不等于来源缺失；不完整响应不作为快照提交；合法空快照必须有来源契约证明完整性。来源观察和来源有效性不等同用户隐藏或学校取消。
- 定时重叠默认展示冲突，用户显式“不冲突”优先；全天不参与重叠处理。派生默认不自动写为用户确认。PlanBlock 结束不自动执行或完成；个人事件的完成由用户在应用内确认，不为完成确认发送系统通知。
- 支持个人事件的单次、全天、跨日、基础重复与单次例外，Task 状态和规划状态分开；出勤决定、听讲模式和备注分别记录。工具数量、提醒偏移、撤销额度等参数在相关设计时重新确认。
- 需要保留的业务资产须有明确迁移和回退方案，不能预设唯一输入为旧 v7 库。2026-10-09 用户确认当前旧业务数据价值低且可重取，本轮选择新工程独立空库起步，旧资产不迁移、不作为 M0 前置门槛；未操作旧目录，未来新数据继续适用连续性约束。

### 安全与工作约束

1. 密码、模型 Key 受保护持久化、按需使用；P 只提供保护与解密能力，带保护元数据的密文由 C3 业务库作为唯一持久事实源，不另建平台秘密存储事实源。临时明文最短存活并尽力零化，不承诺绝对清除。模型 Key 仅用于其绑定的固定模型服务（学校或 DeepSeek 官方，见[提供方决定](../decisions/model-providers.md)），两套 Key/同意独立且不自动回退；密码只用于经验证的学校认证页面。两者不进日志、审计、工具或非目标出站。
2. 浏览器认证资产保持不透明：应用自有代码不读取 Cookie、Token、Storage、IndexedDB、认证 header 等资产。浏览器运行时在受控隔离分区中管理它们；P 仅提供生命周期能力，来源只消费必要业务数据和身份判定。
3. 外部请求最小化并按需授权；评课首次联网须告知并获授权，只发送必要课程、教师检索词。页面、点评及附件内容是不可信数据，不能成为 Agent 指令；Agent 对学校与外部系统只读，本地写有风险分级、确认与事务审计，审计安全摘要不存 DB id/ref 或原文。权限变更由用户亲手确认。
4. 用户可清除凭据、会话、业务和 Agent 历史；清理失败保持明确恢复状态，迟到结果不能重建数据。原始响应只在用户显式要求时存私有目录；秘密、原始响应、会话资产不进入 Git、日志或发布包。
5. 北京时间为唯一业务时间解释；一源一通道；导入和本地写在提交事务内复验账号、维护状态和租约版本。自动测试不访问学校网站，凭据、验证码和授权确认由用户操作；自动结果与人工验收分别记录，原失败与用户验收结论保留。
6. 按本分支 AGENTS.md 及 [15 当前工作流标准](../workflow.md)使用 Sol 总负责、Luna 承接明确任务、Sol 集成验收、Astra 按需参与的协作方式，使用普通文档与 Git。不复用旧代码、测试、fixtures、CI 或施工流水线，不修改其他 worktree，未经用户要求不推送。里程碑关闭执行 analyze/test/build；纯文档修改执行相关文档检查。

### 教务日常认证范围（2026-10-10）

用户确认日常采集包含加密凭据和自动认证，并明确学校重新要求密码不阻塞 M1。用户可以在应用主动提供账号密码，明确选择本机加密保存后用于固定教务认证页面；验证码、通行密钥及学校额外授权仍由用户完成。这个授权不允许读取浏览器手填秘密或认证资产，也不扩大为学校业务写操作。保存新凭据须与有效身份/快照的成功导入同事务提交；用户可以独立删除保存的密码。具体运行与检查见 [15 同一 M1 任务](../milestones/m1/records/02-collection.md#m1-业务契约验证与采集接续任务2026-10-10)，不能用计划或本机合成结果替代真实学校验收。

### 学校账号与二课自动认证范围（2026-10-11）

用户要求二课采用与 M1 相同的自动认证、查询和采集链路，并明确“两个账号是完全一样的，大部分逻辑可以复用”。JW 与 Young 复用同一个本地学校账号、已保存的受保护密码及固定 CAS 认证逻辑；本条替代 M2 观测准备阶段不复用 JW 凭据、学校登录仅手动的临时范围。两个来源仍分别持有浏览器分区、作业戳、业务身份核验和具体认领许可，不能以教务验证结果放行二课。

自动认证只使用用户主动在应用提供或此前明确保存的密码，在当前学校认证文档单次投递；验证码、通行密钥、额外授权和无法安全识别的页面仍交用户操作。二课新密码仅与成功核验的正式查询或日程导入同事务保存，失败、取消和回滚保留旧密码。清二课登录资料保留共享密码与教务资产；单独删除保存密码影响两来源，界面须明确说明。真实自动化结果与本机合成检查分别记录于 [15 接续任务](../milestones/m2/records/03-production.md#m23-真实失败与自动认证接续2026-10-11)。

### 校园精选文本知识库与 M3 范围

按用户 2026-10-11 的选择，M3 为未来 Agent 查询公开信息准备内部能力：评课在线查询、教务/财务公开检索与读取、精选长期 Markdown 知识库。正式用户通过后续 Agent 使用，不提供独立搜索、资讯或知识库产品入口。M3 不生成或注册 Agent 工具、不接模型；内部接口须便于后续 C4 适配，临时人工验收界面只调用同一能力，不承担业务规则。具体取舍见 [范围决定](../decisions/public-text-knowledge.md)，范围与关闭条件见 [M3 任务单](../milestones/m3/plan.md)，不把本阶段基础能力通过记为 Agent 已实现。

选定 HTML、必要文件和正文图片在开发时转换，MinerU 辅助、困难内容由 Luna / max 整理，Sol 原页校核；工具不装配到应用。保留必要结构、出处、版本与质量状态，C3 是导入后文本的持久权威，原始二进制不长期保存。缴费/选课通知等时效消息排除入库，保留在线读取能力。结果携带可供后续 Agent 展示的原文链接，用户自行查看/下载，不装配下载管理；需要账号登录的材料跳过。

用户明确本机在校园网、代理为 7897，授权在明确校园 IP 限制时用本机直连复验。只改变已注册校园请求的路由，不改全局代理，不降低 TLS 或绕过账号授权，应用自有请求逐跳复验继续有效。实现和实证分别验收，不因路由授权宣称所有页面可达。

### 首版浏览器安全边界与 M0 准入

2026-10-09 用户先回复“approve，现在能开始M0了吗”，批准首版有限浏览器边界与本地 M0 分段准入；随后讨论降级安全限制，并回复“approve，请修改设计”，批准将严格浏览器网络隔离移出首版设计。以下为 DR-ADR-09/10 的最新范围，替代此前把全部协议出站封闭作为施工或放行前提的规定：

- 应用自身的来源请求和模型请求继续限定目标、必要字段及授权，默认拒绝未经许可的请求；应用/Agent 主动执行的学校业务操作仍只读，认证动作许可独立。凭据保护、认证资产不透明、独立会话、文档关联、真实清理、事务和用户主权继续有效。
- 首版浏览器限制顶层与 frame 导航、弹窗、下载、权限申请和外部协议，采集仅执行来源登记的固定操作/脚本；Agent、模型输出与外部文本不能提供任意 URL、浏览器脚本或点击能力。来源特定的常规自动请求规则仅在执行可靠、兼容性已验证时采用，并单独说明实际覆盖；不要求对页面网络实行全局默认拒绝。
- 首版不主动注入 CAL，不安装为全协议封闭而设的 DNR/CSP 防护扩展，不一律禁止 Worker，不以 JS 替换或封锁 WebRTC。浏览器尊重页面及服务端已有的 CSP/CAL 等策略，不删除或放宽原策略来规避故障。学校页面及其依赖脚本按普通 WebView 运行，接受其正常后台网络活动；不保证全部协议白名单或零外联，也不以后台流量证明应用主动操作只读。这是用户已接受的首版信任边界。
- CAL 引擎修复、取得含补丁运行时及全协议漏拦回归均移出首版任务与 M0、真实观测入口、整体冻结/发布的必需条件；不主动追踪候选版本或继续修复该增强路线。原失败和回归工具留档，不改为通过；以后实际产品或学校页面发生同类故障，再按普通兼容性问题处理。未知后台流量或全协议覆盖不足本身不使来源 unavailable，身份、响应契约或保留控制未通过仍阻止对应能力启用。
- 本地基础 M0 可以先用全新合成来源、独立演示目录和数据库实现最短链路。真实学校接入、身份/响应/完整性契约及浏览器产品装配仍独立验收，未成立的来源保持 unavailable；在扩展来源实现前尽早做用户辅助观测。M0 准入不等于整体设计冻结、里程碑完成或正式发布。

首版浏览器验收覆盖实际登录、来源身份与正确采集、取消、关闭和清理，以及保留的具体控制；不要求运行 CAL 资格套件、证明所有协议没有漏拦或证明 Worker 被全部禁止。应用自有请求与网页自然运行的网络活动分开解释，前者继续适用目标、必要字段、授权和只读约束。规则批准本身不替代工程实现、来源验收或底层引擎修复的证据。

### Android 普通系统 WebView 兼容映射（2026-10-17）

用户已批准 Android A7-W1–W6 采用普通系统 WebView 路线，详见[兼容修订决定](../decisions/android-system-webview-compatibility.md)和[迁移计划](../milestones/android-apk/plan.md)。这是 Android 浏览器执行环境的明确例外：获准学校同源页面脚本作为可信执行环境，固定认证与采集脚本可在普通页面世界运行；不再声称抵御恶意或被篡改的学校同源脚本，也不保证同源脚本看不到密码。原生控制仅覆盖平台实际可观察的导航并据此拒绝未知主页面和旧操作；不声称封闭所有 frame、POST、中间重定向或 opaque 导航，也不设置全 frame 就绪门禁。既有固定操作、外部协议/弹窗/下载/权限控制、凭据单次租约、身份/事务核验和页面已有策略继续有效。

Android 学校会话改用独立、按分区选择数据目录后缀的专用宿主进程；撤销必须持久化，旧宿主和执行体必须确认停止，且须以平台契约和合成隔离证据正面证明新分区有独立认证存储，才可把仅未完成物理删除的旧残留登记为可见的隔离待清理项并启用新分区。无需先可靠限定旧分区 owner、旧后端、全部历史布局或每个遗留文件的精确位置；未知归属/位置的残留继续待清理，不得猜路径删除、重用旧分区或报告清理完成。若不能证明新分区不会与旧/遗留认证存储共享，或撤销、停止、排空、新分区所有权任一未决，仍阻止新学校宿主。C2/C3、来源许可、事务与 Keystore 凭据权威不变；Windows 及其他平台的必要恢复失败仍按原规则阻止正常启动。此修订只适用于 Android，不削弱 Windows 现有认证文档绑定或 Windows 1.00 实现与验收；也不把计划、旧 A2 证据或文档规则记作 W1–W6 已通过。

### 本轮审核补充规则

- 同一规范化应用数据目录只允许一个活动进程。P 提供覆盖进程生命周期的排他所有权，C5 在开库、迁移或分区调和前取得；第二实例只激活既有实例或退出，不打开资产。进程内全局来源租约不能替代这一边界。
- 活文档动作能力与不可变采集产物分开。C1 在有效文档、身份和作业上下文中封存身份判定及业务产物后只做收口；正常关闭不撤销封存产物。C3 仍在事务内复验账号、原 generation/epoch、契约与完整性，取消或维护拒绝未提交旧产物，不引入签名协议。
- 既有账号无可用会话时允许重认证重建 provisional 分区。首登或恢复成功事务必须写入绑定具体 partition、attempt、owner 和 resetEpoch 的持久认领许可；P 认领与启动调和只依据匹配许可，账号存在本身不构成许可。无许可候选回收，deletePending 先完成清理；提交后取消不撤销许可，清会话或 reset 可撤销。
- 首登、重认证及换模型 Key 的新密文与必要配置、审计同事务提交；保护失败或 SQL 失败保留旧事实，不宣告成功。平台保护机制与跨设备可解密性须实证；用户直接在浏览器手填时，应用不读取页面秘密。
- 本地命令由受控入口生成稳定操作身份，绑定不可变意图、账号/epoch、必要批准和目标版本。相同操作重放返回已有提交结果，内容改变不能沿用批准；新执行仍由 C3 复验当前权限。内部回执与安全审计分开，具体字段、表和保留期限在 V-06 确认。
- 取消与提交以 C3 事务先后为界：取消先受理使未提交操作失效；先提交保留 committed，取消只停止可中止后续，必要认领和资源清理仍须完成或进入恢复。
- C1 定义来源出站策略，P 按 DR-ADR-09 执行导航、弹窗、下载、权限与外部协议等保留控制；来源特定的常规请求规则按已验证范围执行，不扩展为页面全协议封闭。只用必要请求元数据判断，不读取认证 header 或 body 中的秘密。认证动作许可不扩展为应用主动学校业务写。模型网关目标限定为用户当前选择的提供方固定主机，带 Key 请求默认不跟重定向，工具不能指定目标；应用自有公开 HTTP 每跳复验来源契约。保留但不能证明的平台能力列入 V-02，不记支持；已明确排除的全协议隔离不再列为首版待关闭缺口。
