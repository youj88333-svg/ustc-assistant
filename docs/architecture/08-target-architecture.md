# 08 本分支目标架构

## 本分支当前规则

2026-10-09 按 [07 当前决定](07-constitution.md)修订。C0–C5 和 P 表示单 Flutter 工程中的模块职责；模块细分、完整数据模型和新来源契约按对应阶段验证。JW/Young 的当前具体契约见 [来源参考](../reference/sources/README.md)，不据历史结论宣布冻结。

### 系统边界与依赖

产品保留五条来源及本地日程、任务和 Agent。学校认证使用用户主动提供凭据的固定自动链路，验证码、通行密钥及额外授权由用户在可见浏览器中完成；公开来源经受控 HTTP 获取；本地数据由本应用独立管理，应用密码及模型 Key 的密文与保护元数据统一持久化于 C3 业务库。新工程运行时不含 Python、Bridge、CLI 或旧工程租户。旧工程保留在原 worktree 作可运行参考。

P 为同一规范化应用数据目录提供覆盖进程生命周期的排他所有权；C5 必须先取得所有权，才允许开库、迁移、调和或访问该目录中的其他资产。第二实例激活既有实例或退出，不打开资产；无法确认仍持有所有权时停止资产访问并进入安全退出或恢复。C2 的全局单作业只解决所有者进程内仲裁。

| 模块 | 唯一职责 | 允许调用 |
|---|---|---|
| C0 共享核心 | 时间、稳定错误、必要通用值对象和安全能力端口；不含来源业务或凭据仓库 | 无业务模块依赖 |
| C1 来源引擎 | 来源请求、导航与身份语义、会话生命周期编排、规范化及完整性校验；不写业务库 | C0、P 端口 |
| C2 来源作业协调 | 所有来源作业唯一入口；全局单作业、来源注册、一次性凭据租约、暂停恢复取消及结果交接 | C1、C3、C0 |
| C3 本地数据与业务 | 账号、受保护密文、分区认领许可、导入、业务服务、用户覆盖、公开知识材料文本/索引、操作回执、审计、维护持久状态、迁移和回退的事务权威 | C0、P 文件/通知/安全端口 |
| C4 Agent | 模型调用、上下文、工具、审批与隐私；通过业务服务读写本地，通过 C2 查询来源 | C2、C3、C0 |
| C5 应用壳层 | 页面、路由、组合根及启动、首登、维护等跨模块用例编排 | C0–C4、P |
| P 平台适配 | 进程排他所有权、浏览器、凭据保护/解密、受控文件、通知和外部链接执行；不决定业务身份或来源展示规则，不另持久化应用密码、模型 Key 或知识库事实；开发资料转换工具不属于 P 的应用装配 | 对应端口定义、平台 SDK |

端口在职责归属模块定义，P 提供实现，由 C5 注入；调用方向与端口实现的编译依赖分别检查。C0–C4 的业务核心不引用 Flutter Widget 或直接持有平台资源。网络能力限定为 C1 的来源获取、C4 的学校模型网关，以及 P 执行的受控浏览器导航和外部链接委派。

C1 定义应用自有来源请求及浏览器导航/采集策略，P 按 07 DR-ADR-09 执行顶层/frame 导航、弹窗、下载、权限申请和外部协议等保留控制。来源特定的常规自动请求规则仅在可靠且兼容性已验证时采用，声明其实际覆盖；不把所有页面后台请求纳入全局默认拒绝。只消费必要请求元数据，不读取认证 header/body 秘密；应用主动学校业务操作只读，认证许可不授权业务写。采集脚本与目标固定登记，Agent 不持有任意浏览器执行能力。应用自有公开 HTTP 每跳复验来源契约。C4 从受控配置取得学校模型网关目标，带 Key 请求默认不跟重定向，工具无目标地址输入能力。

首版 P 装配采用普通 WebView 运行页面，接受页面及其依赖脚本的正常后台网络活动，不承诺全部协议白名单或零外联。不主动注入 CAL，不安装为全协议封闭而设的 DNR/CSP 防护扩展，不一律禁用 Worker，不以 JS 替换 WebRTC；尊重服务端及页面已有安全策略。CAL 修复、补丁运行时资格与全协议漏拦回归不再是首版或观测入口的前置依赖，也不主动追版本。原失败和工具留档；实际学校页面出现同类故障时按兼容性问题处理。

保留控制的执行与真实来源兼容性分别验证；不能证明的保留能力列入 V-02，不能仅以接口存在宣称支持。已排除的完整网络隔离不再属于首版待关闭的平台缺口，也不因未知后台流量将来源判为 unavailable；来源身份、响应契约和保留控制仍须满足启用条件。

### 来源注册与仲裁

注册表分别声明来源键、能力（完整快照或只读查询）、传输（认证浏览器或公开 HTTP）、有效契约版本和唯一实现。教务、二课日程可同步；二课报名、评课、校园信息不因枚举成员关系自动加入日程同步。教务处与财务处是校园来源的两个提供方；精选长期材料的校核 Markdown 是受控本地输入，不构成第二网络通道，由 C3 持久管理，不生成日程。公共作业上下文与知识库生命周期见 [09 K-07](09-contracts.md#k-07-公开文本材料与知识库)。

生产装配每个来源只有一个实现；测试替身通过独立测试装配注入，不成为生产的备用通道。所有来源执行均经 C2；同一时刻至多一个来源作业持有全局租约，暂停期间保持持有。C3 持久管理来源 generation 和 reset epoch，取消及维护使未提交旧结果失效，未交付的查询结果不能迟到入对话。取消与提交由 C3 事务次序裁决；已提交事实保持 committed，取消不撤销已提交认领许可，必要认领及清理仍完成或恢复。

C2 分别观察来源终态、C1 资源收口及 C3 导入/结果交付完成。全局租约在必要收口与交接完成后才释放，C5 的 idle 来自 C2；来源 complete 不直接表示业务导入成功。首登、重认证和普通查询使用同一仲裁入口及恢复语义。

### 公开信息与 Agent 接入边界

评课及校园公开搜索、读取和知识库为未来 C4 提供内部能力，正式用户经 Agent 使用，不另建独立查询/知识库产品入口。C1 定义来源语义，C2 是在线请求入口，C3 是本地检索/版本事实权威；端口不依赖 Widget、模型 SDK 或提示词。后续 C4 适配工具参数、授权及安全结果投影，只调用 C2/C3，不直接访问来源适配器、数据库或文件。

M3 不注册 Agent 工具或接模型；C5 可装配临时验收入口调用同一内部端口并展示证据/状态，不持有查询、分页、排序、索引或更新规则。入口与正式路由隔离，移除不影响能力及契约测试。只读检索与资料维护分别声明，查询不隐式载入/更新/清理；输入、受控引用、有界结果及出处语义以 [09 K-07](09-contracts.md#k-07-公开文本材料与知识库)为准。

### 会话与平台边界

C1 每次使用认证来源都执行该来源有效身份契约；会话健康不替代身份匹配。P 不透明管理分区和运行时资产，登记 provisional 的 initial/recovery 用途、attempt、partition、owner、resetEpoch 及清理状态。既有账号无可用分区时走同一重认证仲裁并重建候选；C3 仅在首登或重认证成功事务内写入具体候选的持久认领许可，C5/C2 据许可调用 P 认领。启动先按许可调和，账号存在不能自动认领未验证候选；无许可候选回收，deletePending 依平台契约收口。Android 仅在本章所述隔离已证明的物理残留状态可延迟删除；不满足条件时仍阻止新学校宿主。持久分区可复用不等于本次作业已核验。

浏览器事件与动作绑定会话实例、主文档和一次操作；就绪不能由不同文档凑齐。填表绑定实际认证 origin，业务提取绑定来源业务文档。关闭句柄、浏览器资源释放和分区真删除分别有完成条件。Windows 适配器须在设计冻结前证明这些能力；Android 按已批准的普通系统 WebView 映射执行，但宿主生成的文档/操作关联不等同于浏览器签发的文档身份证明，实际导航覆盖、隔离和恢复仍待 A7-W1–W6 验证；iOS 另行验证。

Android 以不导出的独立学校宿主进程运行系统 WebView；主进程继续持有 C2/C3、学校凭据、业务数据库和许可权威。宿主单个进程生命周期只使用一个已登记分区：先持久写入后端版本、分区引用、随机数据目录后缀和恢复状态，再于任何 WebKit 初始化前设置该后缀并创建 WebView。宿主 IPC 限定当前实例、来源、会话、epoch、分区与固定操作，不接入 FlutterEngine 或业务库；旧 AndroidX Profile 仅用于受控恢复和隔离，不作为日常第二通道。具体浏览器信任例外及残留状态见 [09 K-02/K-03](09-contracts.md#k-02-分区生命周期与归属)。

Android 分区撤销、宿主停止与排空确认、新分区所有权/后缀和物理删除分别持久记录。只有撤销已提交、旧执行体已停止、旧提交资格已终止，且平台契约和合成证据正面证明新后缀不会与旧/遗留认证存储共享时，才可将未完成的旧物理删除记为可见隔离待清理并启用独立新分区。无需可靠限定旧分区 owner、旧后端完整布局或所有旧文件的精确位置；未知归属/位置的残留继续待清理，禁止猜删或宣称清理完成。不能证明新旧认证存储隔离，或撤销、停止/排空、新分区所有权未决时，仍阻止新学校会话。Windows 及其他平台的必要恢复失败仍阻止正常启动；此映射不改变 Windows 的认证文档绑定、删除收口或 Windows 1.00 基线。

C1 在仍有效的上下文中校验并封存不可变采集产物，绑定身份判定、业务数据、来源/契约、分区和原作业；封存后只允许收口。活文档动作能力随关闭失效，正常关闭不使已封存产物失效；C2 只交接该受控产物，C3 在提交事务内继续复验账号、原 generation/epoch、有效契约和完整性。该边界不引入签名协议，也不允许封存绕过取消或维护守卫。

C3 使用 P 保护/解密能力，持久化密文及保护元数据；首登、重认证或换 Key 的保护失败、SQL 失败均保留旧事实。新密文、必要配置及审计同事务提交，不用额外平台秘密存储形成第二事实源；纯浏览器手填不读取页面秘密。C3 同样是本地命令的提交与回执权威：受控入口生成稳定操作身份并绑定不可变意图、账号/epoch、必要批准和目标版本，重放已有提交只返回回执，内容改变须重新批准，新执行复验当前权限。

### 数据与技术选择的状态

Flutter/Dart、Material UI、本地 SQLite/Drift、平台凭据保护能力和北京时间解释保留为设计路线。保护机制及跨设备可解密性须实证，模块分包、状态管理、路由形态及具体平台包按需要决定。新 Schema、资产迁移输入、序列化协议版本和参数不继承旧 v7/v8、30 表或旧代码为权威；业务数据目录与旧工程独立。允许受控只读资产元数据清点，完整映射先于一致副本转换，验收先于发布，原件不写。

模块边界和首版准入依据 [决策登记](../decisions/README.md)。当前阶段交付范围见 [状态页](../status.md)与 [阶段验收](../milestones/README.md)，来源参考维护各自已实证的具体契约。C4、完整本地业务/工具/提醒等仍在对应模块阶段补齐，局部验收不表示整体设计冻结或其他能力通过。
