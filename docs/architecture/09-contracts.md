# 09 本分支关键契约

## 本分支当前规则

2026-10-09 按 [07](07-constitution.md)与[08](08-target-architecture.md)修订。下列契约约束已获批准；已实证的来源具体行为见来源参考；新来源、序列化及完整数据模型按后续阶段继续验证。当前定义不继承历史 CT 的冻结状态。

### K-01 来源契约与可信身份

C1 为每条来源维护独立 `SourceContract`，至少声明：来源键与版本、允许的认证/业务 origin、应用主动执行的只读请求/采集操作和浏览器导航规则、响应成功/错误/未登录形状、身份依据、完整性与稳定外部身份规则。该声明不要求列举或封闭页面自行产生的全部后台网络活动；额外常规请求规则须单独声明已验证范围。JW、Young 的身份字段、规范化及与本地账号的映射各自验证；公开来源不申请学校凭据。

可信依据必须是该来源已验证、与当前认证会话及业务文档关联的服务端业务身份数据。Resource Timing URL 参数、客户端自报账号、Cookie/Token/Storage、单纯到达页面、接口可达或用户点击确认均不单独构成依据。提取仅消费必要业务字段，禁止读取浏览器认证资产。来源契约未验证时保持 unavailable，不允许用合成样例补出生产证据。

身份结果只向受控作业链交付判定与上下文：来源及契约版本、jobId、会话实例、主文档标识和判定；不向 UI 事件、工具、日志或审计暴露实际账号或原始证据。C3 从自身持有的预期账号及成功判定绑定本地身份，不接受调用方任意提供的 identity digest。动作及提取时，判定必须属于当前作业、会话、文档和契约版本；C1 在这一有效上下文中复验后，才可将判定与对应业务数据共同封存为不可变采集产物。产物保留来源、契约、分区、原作业及采集文档关联，只供受控消费者交接；它不继续授权活文档动作，正常收口不撤销它，提交资格仍受 K-04/K-05 守卫约束。

| 判定 | 稳定结果 | 处置 |
|---|---|---|
| 有效依据证明预期账号 | matchesExpected | 继续当前作业；不自动许可跨文档复用判定 |
| 没有可用依据或证据已过期 | identity_unverified | 不交付；关闭本次句柄，保留正式分区，后续作业重新核验 |
| 已定义的业务身份证据相互冲突 | identity_evidence_conflict | 不交付；保留正式分区，不以猜测触发物理删除 |
| 有效依据确证另一账号 | account_mismatch | 不交付；隔离受影响分区、排空占用后清理；失败保持隔离及清理待办 |

上述规则同时适用于 JW、Young，不保留 JW 的“无法核验即串号”特例。重新认证的表单账号与既有本地身份不符为 `identity_mismatch`：在开启学校作业前拒绝，不因此删除既有分区。首登或恢复尚未提交认领许可的候选分区按 K-02 回收，不属于保留正式分区的情形。

#### 具体来源契约

JW 和 Young 的固定 origin、请求/字段、完整性、稳定键、时间和当前实证范围分别维护在 [JW 参考](../reference/sources/jw.md)与 [Young 参考](../reference/sources/young.md)。两个来源各自取得本阶段正式验收，候选探针仍不授予生产许可。具体契约遵守本节通用身份与 K-02–06 守卫。

### K-02 分区生命周期与归属

平台会话端口至少提供下列语义；具体 SDK 映射在可行性验证后确定：

| 操作 | 提供方与调用方 | 必须满足的条件 |
|---|---|---|
| createProvisionalPartition(owner, purpose, attempt, resetEpoch) | P；C1 经 C2 首登或重认证编排调用 | 在创建认证资产前原子登记 provisional 归属、initial/recovery 用途、attempt 和随机 partition 标识，返回不透明 ref；登记失败不创建可用分区 |
| openClaimedPartition(accountId) | P；C1 | 仅已认领且未隔离/待删除的分区可打开；每次作业重新核验 |
| closeAndDrain(ref) | P；C1 | 关闭句柄并等待所属浏览器资源释放，失败不报资源已收口 |
| claimPartition(ref, committedPermit) | P；C5/C2 | 仅凭 C3 已提交且未撤销的持久认领许可，逐项匹配 partition、attempt、owner、resetEpoch 后认领；deletePending 禁止认领；幂等，不重新写入业务身份 |
| markDeletePending(ref) / clearPartition(ref) | P；C1/C2 维护流 | 先持久标记，再停止占用并真清理；失败保留登记和禁复用状态，成功才移除登记 |
| reconcilePartitions(committedPermits) | P；C5 启动流 | 检查所有登记分区；deletePending 仍先撤销、排空并真清理。provisional 仅凭 C3 已提交有效许可认领；claimed 也必须有匹配具体 partition/attempt/owner、未撤销且属于当前 resetEpoch 的许可。无有效许可的候选回收，claimed 缺许可、许可撤销或不匹配则持久隔离/标记 deletePending；不能凭 P 的 claimed 标志或 accountId 存在复用。Windows 及其他平台的必要恢复失败仍阻止正常启动；Android 仅在下文条件证明新分区认证存储独立、且唯一未完成项是旧残留物理删除时允许隔离待清理继续，其他必要恢复失败仍阻止正常启动/学校宿主 |

P 私有登记只保存应用归属、用途、attempt、分区随机标识、resetEpoch、生命周期状态及必要版本，不保存 handle、密码、Token 或身份响应；Android 另登记 backend/version、提供方、数据目录后缀及隔离/清理状态。仅本应用独立受控目录中的分区可被认领或清理；不扫描、接管或删除系统浏览器及旧工程分区。未登记或元数据损坏的本应用分区禁止复用，由受控目录调和处置，不能当作已清理。

既有账号没有可用 claimed 分区时，C3 先校验重认证输入仍属该本地身份，C2 仲裁后以 recovery 用途新建候选。普通 deletePending 不能通过新建候选绕过，须先完成必要清理；Android 下文定义的隔离待清理状态只允许另建已验证独立的新分区。候选按 K-01/K-03 核验并封存成功产物后，C3 在首登或重认证成功事务内写入绑定具体 partition、attempt、owner、resetEpoch 的持久认领许可；账号已存在、用户确认或分区页面可达都不能替代成功核验与许可。

首登或恢复候选在提交前取消、校验失败或事务回滚，均必须收口并回收其 provisional 分区；崩溃在启动时执行同一规则。提交成功而认领失败时，事务保持已提交，进入恢复页；重新读取 C3 已提交许可后幂等认领，不把成功事务改记失败或重新导入。提交后的取消不撤销许可，必要认领仍完成或恢复；清会话或 reset 先由 C3 持久撤销相应许可并使旧操作失效，再按删除待办排空清理。若在 C3 撤销成功、P 标记删除前退出，启动调和仍按许可检查 claimed 分区并持久隔离；Windows 及其他平台的必要恢复失败保持正常启动屏障。Android 仅在启动恢复正面证明下述新旧存储隔离条件，且撤销、旧执行停止/排空、提交资格终止均已确认时可把旧物理残留转入隔离待清理；旧 owner、后端、全部旧文件归属或路径未知本身不阻止另建独立新分区，但未知残留不得猜删或报清理完成，隔离条件不明仍阻止新学校宿主。

#### Android 普通系统 WebView 分区映射

本段是已批准 Android A7-W1–W6 的平台映射，见[兼容修订决定](../decisions/android-system-webview-compatibility.md)和[唯一实施规格](../milestones/android-apk/plan.md)。Windows 原有强认证文档绑定、分区回收和 1.00 结论均不变。

Android 使用独立且不导出的学校宿主进程承载系统 WebView；主进程持有 C2/C3、C3 数据库、Keystore 凭据、事务和认领许可。宿主不持有 FlutterEngine 或业务数据库。创建 WebView 前，先持久登记 backend/version、partitionRef、随机目录后缀、owner、attempt、resetEpoch、提供方和恢复状态；在该宿主生命周期内只使用一个分区，调用 setDataDirectorySuffix 必须早于任何 WebKit 初始化。该 API 自 Android API28 可用，是学校宿主技术下限候选而非安装下限或已通过机型范围；API24 安装和 API28+ 目标提供方仍分别按迁移计划核验。同一后缀不得并发或跨来源复用，宿主槽位采用跨进程排他锁。备份排除这些浏览器目录和恢复元数据；旧 AndroidX Profile 仅留作恢复/清理，不是第二条日常通道。缺少旧账本不能证明没有旧资产；不得迁移 Cookie、Token、Storage 或手填秘密。

Android 在 deletePending 之外增加独立的 `isolatedCleanupPending` 物理清理状态。只有 C3 撤销已持久提交、旧宿主与 WebView/renderer 已停止并获排空确认、旧提交资格已终止、新分区的所有权与全新后缀已持久登记，且平台契约和合成证据正面证明新分区不会与旧/遗留认证存储共享时，才可把唯一剩余的旧物理删除工作列为此状态。无需可靠限定旧 owner/backend、旧分区完整布局或所有旧文件的归属与精确位置；未知残留继续可见待清理，禁止猜测删除或报删除/重置成功。该旧分区永久禁用且不可重用；可对新分区完成许可/归属登记后继续。撤销失败、宿主或 renderer 仍活、排空失败、新分区所有权/后缀或新旧认证存储隔离不明、C3/密钥/数据库/可信恢复元数据失败均不符合例外：必要恢复仍阻止正常启动并拒绝新学校宿主。此物理残留不阻塞与该校通道无关的本地日程及已证明独立的 Agent 能力。真正删除仍仅限本应用拥有且路径可精确限定的目录，不扫描或猜测路径；在平台后缀契约、AOSP 实现和目标提供方验证前，不把目录隔离或删除记为已通过。

### K-03 文档关联与受控动作

`DocumentToken` 是不透明值，绑定会话实例、当前主文档世代；`OperationToken` 另绑定 jobId 和本次等待/动作。P 将平台 NavigationId 或等价能力映射为文档关联，frame 事件分别标识；只凭 URL 相等不能证明同一文档。Android 普通系统 WebView 只能用其原生可观察回调与宿主代际维护有限的主文档关联，不能据此推断 Navigation API、完整 frame 身份或中间请求全覆盖；适用边界见本节 Android 映射。

就绪事件至少带 token 与种类（URL 命中、DOM 就绪、登记脚本握手）。三种证据必须属于同一仍有效的主文档和操作；新文档开始、重试、取消、关闭或会话替换立即使旧操作失效。同一导航的重定向逐次校验规则；同文档路由变化重新核实业务目标，不能沿用过期就绪结果。

上述 token 是活文档等待、动作和提取的能力，不能作为关闭后的动作许可。提取返回时完成文档、身份、结果 Schema 及作业校验后，C1 可封存 K-01 的不可变采集产物，封存后只允许句柄、凭据与资源收口。关闭使 token 失效但不撤销已封存产物；封存前发生切文档或取消的结果仍丢弃，不能以封存补救失效上下文。

fill、click、业务提取分别声明预期 origin、文档和登记操作；密码只允许填入已验证的认证 origin。执行时检查当前文档与 origin；登记脚本在当前文档中核实 origin 后执行，返回时再次检查文档有效性及结果 Schema。发生文档切换即丢弃结果、撤销剩余动作，禁止跨 frame 或跨文档回调凑齐 ready。

Windows 等采用强认证文档绑定的平台仍必须在投递含密码的动作前保证它只会送达指定认证文档；不能仅靠一次早先 URL 检查，或把密码先交给未知文档再执行脚本守卫。Android 使用下述已批准的来源同源信任例外，不继承也不宣称满足该强文档保证；未获该例外的平台若无法证明绑定，仍退回用户手填、不注入秘密。

#### Android 普通页面世界与可观察导航

Android 固定、随包认证和来源脚本在获准学校主文档与来源就绪后安装于普通页面世界，不要求 `DOCUMENT_START_SCRIPT`、私有 JS world、Navigation API、全 frame CSP 或所有 frame 握手。它信任已登记学校 HTTPS 页面执行的同源脚本；不防御恶意/被篡改的同源环境，也不保证该环境无法观察密码。固定脚本的随机文档/操作标记只用于应用侧关联、拒绝迟到结果和发现意外变化，不是浏览器签发的文档身份证明。

密码投递仍只允许固定 CAS 页面与固定表单：原生在投递前复核当前 hostInstance、source、partition、session、epoch、文档/操作代际、固定 URL 和一次性凭据租约，并在投递前消费该租约；使用 `WebView.postWebMessage` 将秘密定向到精确 `https://id.ustc.edu.cn` origin，不将秘密拼入 `evaluateJavascript` 源码、不用通配 origin、不提供页面可调用的取密桥。origin 不限定路径或具体文档，因此“同源学校脚本可信”和可能看到密码是本批准取舍的明确代价；若运行时状态无法满足检查，则拒绝自动投递并收口。验证码、通行密钥与额外学校授权仍由用户处理。

原生保留主动固定导航前检查，以及 WebView 实际提供的主文档/资源回调检查；观察到未知顶层页面、重定向或文档代际变化时立即停止自动操作并使旧 token 失效。WebView 回调不能完整覆盖全部子框架、POST、中间重定向、opaque/blob/srcdoc 等情形；接受普通浏览器与学校策略，不宣称全 frame 封闭。仍拒绝未授权弹窗、下载、网页权限和外部协议；不移除学校既有策略、不加全协议拦截或全局禁 Worker。窗口内不暴露任意 URL、脚本或通用原生桥。

C1 按来源契约声明认证和业务策略，P 按平台实际能力执行 07 DR-ADR-09 的可观察顶层/frame 导航、弹窗、下载、权限申请和外部协议等保留控制；Android 的导航覆盖见上文，不声称全 frame 封闭。各保留控制分别验证，不以顶层 URL 合法推断其他控制有效。来源特定的常规自动请求规则仅在可靠且兼容性已验证时采用，说明实际覆盖，不要求所有页面流量默认拒绝。只用必要请求元数据判断，不读取认证 header 或 body 中的秘密。应用自有主动请求继续严格限定；认证表单的必要动作许可不能扩展为应用主动学校业务写操作。采集只运行固定登记操作/脚本，Agent、模型输出与外部文本无任意 URL、脚本或点击能力。应用自有公开 HTTP 获取在每次重定向跳转前重新验证来源契约。

页面及依赖脚本在普通 WebView 中运行，正常后台网络活动属于已接受边界，不保证全部协议白名单或零外联。首版 P 不主动注入 CAL、不安装为全协议封闭而设的 DNR/CSP 防护扩展、不一律禁用 Worker，也不以 JS 替换 WebRTC；保留页面/服务端已有安全策略，不能删除或放宽它们来规避故障。CAL 修复、补丁运行时资格及全协议漏拦回归移出首版、真实观测入口与冻结/发布的必要条件，原失败和工具留档，不主动追版本；真实产品出现同类故障时按普通兼容性问题处理。

不能证明的保留控制列为 V-02 能力缺口，不宣称支持；已排除的全协议隔离不再作为待关闭缺口。未知后台流量或全协议覆盖不足本身不产生来源 unavailable；身份、响应/完整性契约及保留控制未通过仍阻止对应能力启用。

### K-04 作业、凭据与交接

C2 同步原子取得全局作业租约后才 stage 首登或启动来源。不可变作业戳至少绑定 jobId、受控本地上下文、source、sourceGeneration、resetEpoch；认证作业上下文含 accountId，公开作业使用 K-07 的公共本地上下文，不伪造学校账号。generation 与 epoch 权威在 C3。生产来源没有 Python channel。凭据以不可序列化的一次性租约注入，密码 take 后不可再次取；在用户确认的交互恢复时按需申请，用后尽力零化，取消和维护先撤销未消费租约。

该仲裁以 C5 已取得规范化应用数据目录的进程排他所有权为前提；P 的所有权覆盖进程生命周期，在开库、迁移及调和前取得。第二实例只激活既有实例或退出，不打开资产；所有权不能确认时停止资产访问，不能靠 C2 内存租约继续运行。

P 只提供凭据保护与解密，C3 业务库持久化应用密码及模型 Key 的密文、保护元数据，并作为唯一事实源；不使用额外平台秘密存储形成第二份事实。首登、重认证或换 Key 先保护新值，再将新密文、必要配置及审计同事务提交；保护失败或 SQL 失败保留旧事实，不广播成功。提交前的新明文和密文均按私有临时材料收口。保护机制、适用范围及跨设备可解密性须经平台实证；用户直接在浏览器手填时应用不读取或保存页面秘密。

C4 的学校模型网关目标来自受控配置，工具不能提供目标地址；带 Key 请求默认不跟随重定向，必须先按网关契约另行确认目标，不能转发 Key 到未经许可的地址。模型 Key 的解密、使用和收口仍受一次性使用出口与最短明文存活约束。

C4/C5 经 C2 恢复同一暂停作业，jobId、原业务目标和事件 sequence 保持；恢复请求幂等串行化，过期或非暂停句柄稳定拒绝。登录成功后重新打开该作业业务目标并核验，不将 CAS 默认落地等同数据采集完成。

内部终态载荷与 UI 进度投影分开：内部交接允许受控规范化业务产物和身份判定；公开进度只含作业阶段、安全计数、稳定错误和安全汇总。C1 终态载荷可见后仍须完成句柄、凭据与资源收口；C2 完成必要导入/交付并确认收口后才发布 idle 和释放全局租约。收口失败仍 busy/恢复态，不因 finally 无条件放行新作业。

内部交接消费 C1 在有效上下文中封存的不可变产物，不要求已收口浏览器继续保持活文档能力，不引入签名协议。C3 在提交事务中复验账号、维护状态、原 generation/epoch、有效契约及完整性；取消或维护先使未提交旧产物失效，封存本身不授予提交权限。查询产物也须在受控交付点复验原作业戳，取消后未交付结果不能入对话。

取消受理与提交由 C3 的事务顺序裁决：取消先受理则未提交操作失效，迟到载荷拒绝；提交先完成则结果保持 committed，取消只停止可中止的后续步骤，不反转业务、审计或已提交认领许可。必要分区认领及资源收口仍完成或进入恢复；提交结果、取消受理和后续协调结果分别记录。

教务日常认证已按用户授权具体化：`advanceJwLogin(session, document, operation)` 只返回固定状态；`submitJwLogin` 在同一准备操作中单次消费不可序列化凭据租约，原生入口只增加有界 `credentialBytes`，不接受 URL、脚本或账号目标参数。无秘密 bootstrap 证明唯一隔离 context，秘密调用绑定该认证文档的私有 objectId；密码仅用于 ID 站点的 `/cas/login` 明确表单，其他导航许可不扩大密码许可。重导航、同文档历史变化、关闭或模糊结构撤销投递能力；已提交动作的迟到确认不授权再次提交。

来源选择在作业开始前捕获，并按来源契约复验；缓存目录只供本地选择，不授予身份或采集权限。新目录、成功选择与新密文仅随已核验的查询或导入成功事务提交，失败保留旧事实。清浏览器分区保留加密凭据、目录和业务记录，删除凭据保留账号绑定、目录、日程、导入与分区。当前 UI 只在全局作业空闲时允许删除；作业中须先完成取消和收口，不为删除绕过未完成的排空。JW 的选期及目录限制见 [来源参考](../reference/sources/jw.md#固定入口与只读操作)，M1 的 v1→v2→v3 升级经过保留在 [实施记录](../milestones/m1/records/03-automation-and-display.md)，当前应用版本见 [运行说明](../../app/README.md#目录与诊断)。

### K-05 完整快照、事务与缺失展示

完整快照交接至少包含来源和契约版本、账号/作业绑定、查询范围、完整性证明、计数、采集时间、稳定外部身份的规范化业务数据及幂等依据。SourceBundle 可作为后续序列化候选，旧 1.0 Schema 和错误码数量不自动冻结。确切编码、摘要算法、大小上限和字段表须在真实响应契约及数据模型审查后确定。

C1 先按对应来源契约检查全部行、字段和完整性，再构造唯一稳定外部身份的事件集。只有来源契约明确定义可合并时才合并完全一致的重复项，同键内容冲突整体拒绝，不按数组顺序补身份；来源行数、唯一事件数与合并数分别报告，限额在规范化前复验。C3 只接收已经规范化的唯一事件集，实际导入数量以唯一事件计。具体自然键、合并及覆盖规则由 [JW](../reference/sources/jw.md#完整性重复项与失败)和 [Young](../reference/sources/young.md#日期范围与关联规范化) 分别定义；不从某来源通过推定其他来源契约已验证。

C3 在同一提交事务内校验账号、维护状态、原作业戳、有效契约版本、快照完整性、幂等与引用，再 upsert 数据、来源观察状态和审计。重复同一导入操作不产生重复业务或审计；同一幂等身份而内容不一致稳定拒绝。C1 的 complete、导入事务成功和提醒协调成功分别记录，提醒协调失败不反转已提交业务。

二课每日成功时间与覆盖只由完整日历导入记录：当次携带有效每日许可，或手动/Agent 导入完整覆盖提交当天的每日滚动窗口，才在业务、回执、审计与期望提醒的同一事务内保存。活动列表、未覆盖完整滚动窗口的历史范围、失败、取消、未完成或仅打开学校窗口均不算每日成功；历史范围不覆盖已保存的每日成功事实。同日成功覆盖当前滚动窗口可免去重复自动采集。每日入口的固定范围不改写普通手动同步记忆的日期范围。

来源观察状态 `presence` 保留 `observed`、`outside_scope`、`missing_within_scope` 三种语义；`source_retired` 是独立的来源有效性事实，不由 `presence` 或 UserOverlay 推导，也不写入用户 hidden、出勤、备注、完成或删除状态。只有契约证明完整的选定范围才可更新范围内观察；不完整响应整体拒绝，不能修改 `presence` 或 `source_retired`。

仅完整的 JW 同一选定学期可将范围内缺失的旧课程标为 `source_retired`；考试没有可靠完整覆盖，空考试集不产生此结论。仅完整 Young 所选日期范围可将范围内缺失或已无活动关联的旧日程标为失效。来源细节见 [JW](../reference/sources/jw.md#本地提交与保留语义)和 [Young](../reference/sources/young.md#本地提交与保留语义)。其它学期/日期范围只更新其观察到的 `presence`，不得触碰既有失效位或使它复活；正常的范围外旧课表仍按原日期保留。失败、取消、来源身份或完整性未通过均不部分停用记录。

默认有效投影排除 `source_retired`，包括日历、Agent 当前日程、规划、冲突、晨报与提醒；C3 按同一有效性计算刷新期望提醒，使已登记的失效目标进入普通取消对账。显式历史查询可包含 `source_retired` 并标注“来源已不再返回”，不能把它当成当前有效安排、学校取消或本人报名状态。`CalendarQuery.includeRetired` 默认 `false`；同稳定键按来源适用条件在完整范围内重新返回时清除此位，保留本地身份及 UserOverlay。新自然键（如改日期）不继承旧条目的备注或覆盖。

### K-06 数据连续性与维护

实际资产清单至少列输入格式/版本、所有者、业务范围、稳定身份、关联及覆盖规则、目标映射、验证和回退方式；不包含秘密或原始行。新 Schema 按确认的模型定义，不默认 v7→v8；数据目录与旧工程独立。迁移仅从受控副本读取，经一致备份、完整性及语义校验后发布目标数据；不覆盖唯一原件，不迁移浏览器资产，不迁移未经验证的身份断言。

设计阶段允许受控只读资产元数据清点，用于确认格式、版本和范围，原件不写；该清点不等于转换或发布授权。完整目标映射是从一致受控副本执行转换的前提，完整性与业务语义验收通过是发布目标的前提；不得因尚无完整映射而禁止必要的只读清点。

2026-10-09 用户确认当前所有旧业务数据价值低、可方便重新获取，授权按需要处置。本轮采用新工程独立空库起步，当前不要求旧资产迁移，不将旧版本映射/迁移验收作为 M0 前置条件；未修改或删除旧目录。该选择仅针对当前旧资产，未来新业务数据继续适用连续性、事务及回退约束。

旧账号及其关联可以作为业务迁移的定位信息保留，不作为新来源的认证通过依据；不能因旧身份尚未重新核验而丢弃其业务资产。迁移后的来源访问仍须按 K-01 验证。

schema 16→17 仅为 JW 与 Young 来源事件增加 `source_retired` 列，保留已有业务、提醒及其它资料，并沿用既有增量升级链。迁移时将旧 `missing_within_scope` 的 JW 课程和 Young 日程初始化为失效；不对考试初始化。旧行若已被后续其它范围同步改成 `outside_scope`，现存观察状态无法还原曾经的范围内缺失，需在对应范围重新完成同步后才能作出判断。迁移不访问学校或实际秘密。原提醒行及编码保持兼容；启动按新有效投影重捕获期望态，失效目标经既有对账取消已登记提醒。

schema 17→18 只新增 C3 所有的 `young_daily_sync` 单表，保存默认关闭的开关/修订、每日尝试与退避、成功时间/覆盖、清业务当天抑制和在途认领标记。既有表、来源有效性、用户覆盖、任务、提醒、聊天、凭据及 owner/reset/agenda 状态保持，17→18 不重复执行旧失效回填；更旧版本继续走原增量升级链后创建该表。升级失败回滚且不推进版本，不因升级、重开或已有凭据自动启用。启动作废旧内存许可并恢复中断尝试，不复用上次作业授权。

清空业务在同一维护事务中保留每日开关、清除每日成功/尝试状态并抑制当天自动补建；用户仍可主动同步。完全重置关闭开关并清除每日状态。两种维护均撤销旧许可、排空作业后再清理，失败保持既有维护恢复边界；重新启用或维护恢复不能使已撤销的旧结果重新有效。

首登业务事务原子提交账号、身份绑定、受保护凭据密文、配置、快照、具体候选分区认领许可与审计；提交后才广播业务提交成功，必要认领另按 K-02 完成。重认证保持既有本地身份不可变，成功事务原子更新必要密文、配置、恢复候选许可及审计。普通本地写携带当前维护/账号版本及目标版本，业务与必要确认、审计同事务；确认卡在执行时复验，不因审批通过跳过守卫。

本地命令由受控入口生成稳定操作身份，绑定不可变意图、账号/resetEpoch、必要批准及目标版本；C3 复验当前权限和维护状态。相同操作重放返回已有提交结果，不重复业务或审计；同一身份而意图不同拒绝，内容改变须生成新操作并取得所需新批准。内部提交回执与安全审计分开：回执服务于受控幂等查询，不能因审计脱敏而丢失提交结果，也不能将内部标识或原意图直接投影到安全审计。具体字段、表和保留期限在 V-06 确认，不另建大型工作流框架。

完全重置先持久记录用户删除意图、递增 epoch 并拒新写；撤销凭据租约、取消并收口来源和 Agent，真清理本应用归属的全部会话与相关私有资产，最后提交数据删除。任何必要清理失败保留恢复状态；启动先恢复再开放业务。清业务数据也先阻止新写、排空旧事务并使来源结果失效，范围与用户确认一致。所有删除限定于本应用和本次用户选择的资产，不因历史“全部备份”规则清理旧工程文件。

### K-07 公开文本材料与知识库

本契约按 [校园文本知识库决定](../decisions/public-text-knowledge.md)新增，落实于 [M3 任务单](../milestones/m3/plan.md)；细化接口与限额仍待原生验证。公共本地上下文由 C3 创建并关联当前应用数据所有者，不是学校身份，不能由 UI、URL 或来源响应任意指定；公开来源不申请凭据、不创建学校分区，允许在尚未绑定学校账号时查阅。

公开查询与知识库端口是供未来 Agent 适配的内部能力，不是已生成的工具或独立用户功能。M3 返回与模型/界面无关的版本化结构化结果，后续 C4 再定义模型可见参数、授权和安全投影；临时验收界面只消费同一契约。在线查询仍经 C2，本地检索经 C3，任何未来工具包装不能绕过来源许可、维护世代或结果交付守卫。

检索与按引用读取分开：输入为受控关键词、固定来源/主题/学期等筛选、有界数量或范围；结果返回候选/匹配片段及进一步读取的受控引用。分页延续值和条目/材料引用由能力层产生，关联查询范围、来源契约或材料修订及有效世代；新读取复验归属与当前许可，不接受调用方任意 URL、SQL、文件路径或 DB id。展示出处 URL 只作证据，不授予抓取许可；不得将内部作业/上下文直接序列化为未来模型参数。

结果须表达来源/标题/原文链接、抓取或接受时间、可证的发布/更新时间、材料版本/质量及节/页定位，并区分在线响应与本地版本。返回范围、分页是否可继续、截断及未知覆盖明确表达；有界片段不冒充整篇/全站覆盖，课程评分人数与点评数独立。能力可用性、合法空结果、未验证能力、访问限制、来源失败、过期引用、取消及资源超限稳定区分，不能统一转成“没有结果”；未知日期/适用性保留未知。具体 DTO/错误码在实现切片定稿，不由模型猜补。

C1 仅获取登记目录、受控条目及已验证关联；逐跳复验目标、方法、内容类型和预算。校园代理/直连选择发生在同一受控 HTTP 实现中，不增加隐式备用通道。读取需要账号登录的内容停止；网页、文件、图示及点评是数据，不执行脚本/宏，不产生新权限或自动日程。知识库仅接受选定长期材料，不纳入缴费/选课等时效通知；在线查询临时内容不能借缓存入口持久化为知识材料。

材料产物绑定提供方/稳定文档键、文章与材料出处、范围、原材料摘要、转换/校核版本、Markdown 正文/纯文本片段与定位、时间语义及质量状态。开发时 MinerU/OCR 辅助，困难内容由 Luna / max 完整描述并经 Sol 原页校核；HTML 空正文须排除实际文件/图示，PDF 空白页与扫描页分别识别，词提取不自动证明表格或流程关系正确。样稿或未经质量检查的结果不能作为完整可用版本。

C2 的在线查询沿用 K-04 全局来源仲裁、取消与交付。本地知识库 search/read 不占来源租约；材料载入由 C5 发起、C3 按受控本地操作串行受理，可与来源网络作业并行，SQL 提交仍序列化。C5 管理本地批次进度/取消，C3 复验本地操作身份、公共上下文、reset/知识库 epoch、目录版本、目标修订及维护状态，不构造不存在的来源 job。

本地检索/读取同样复验公共上下文、维护状态和知识库 epoch，按引用读取核对材料修订；清库或换版后的迟到结果不得作为当前证据交付。材料载入、更新与清理是独立维护命令，遵循 K-06 必要批准，不混入只读查询或因网页/未来模型输出自动触发。

投影取最近 180 天内最多 512 条已知提醒，逐日缩小过密查询并明确截断；可确定被更近提醒挤出的旧项撤销，不保留它们挤占近项。未知区间不推断删除。点击依据当前 C3 身份、token、摘要、规则和对象状态定位；过提醒时刻本身不等于目标失效，已展示项最多保留 30 天映射。点击不写业务、不恢复授权或旧对象。

活动进程在已登记候选投递后滚动对账，最迟每30分钟校准窗口，恢复前台时合并触发一次；失败延后重试，不作紧循环。不扩大180天/512上限、不补弹过去提醒；关闭进程后仅由OS执行已登记计划，没有额外后台服务或自动新增计划的保证。未启用时不安排周期轮询或注册OS，维护及正常关闭取消本地轮询。

`MorningBriefDataPort` 保存每日输入摘要、认领票据、运行/模型尝试计数、阶段、必要公告片段及结果。北京时间 06:00 后在前台首次使用自动尝试；只读当天日程/状态、截止任务和冲突计数，不含备注、任务正文、图片、音频、账号和内部 ID。公告仅取昨天登记的教务/财务通知；完整日期才接受，未知日期、失败与部分覆盖不能变成“没有公告”。自动最多两次运行/模型尝试，手动重试主动触发；同日复用，关键事实变化后旧摘要不当当前版本显示或提交。

晨报独立于主对话，不调用工具、不创建聊天或改变 Agent 权限。模型复用用户已保存配置及同意，估算输入不超过 4000 token、输出上限 600 token；主对话正文不作为输入。缓存保留 30 天/5 MiB，清缓存抑制当天自动重建，用户可手动生成。阶段和失败使用固定枚举，日志不得含事实包、响应正文或激活参数。

晨报摘要在内部区分 `today` 与 `notices`，解析通过后才呈现自然文字，JSON 不展示给用户。两固定来源的昨天范围均完整才发起模型摘要；部分覆盖/失败直接使用由应用生成的今日事实版，不消耗模型请求，已取得通知及来源状态仍可在面板读取。未知覆盖时不能只靠模型自报的字段判断内容安全，旧的未分段或模型段摘要都不展示；不修改或推断原始业务。手动重试重新读取公告，自动中断恢复只复用完整批次。安全日志按教务/财务分别记录固定阶段、失败码、成功页数和覆盖结果，使用独立诊断关联号，不含标题、URL、日期事实或摘要。
