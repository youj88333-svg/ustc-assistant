# 学校账号、自动认证与共享凭据

状态：已采纳。2026-10-10 用户确认重新输入学校密码不阻塞 M1，要求日常采集包含本地加密凭据、自动认证和学期记忆；2026-10-11 明确 JW/Young 使用同一账号，大部分认证逻辑可复用。原实施及真人结果见 [M1](../milestones/m1/records.md)、[M2](../milestones/m2/records.md)。

## 决定

用户在应用主动提供的账号/密码可在固定、当前学校认证文档中单次自动使用。Windows 使用既有 DPAPI CurrentUser 整体保护和用途绑定，C3 保存一份学校凭据事实，两来源分别核验身份并申请一次性租约；不复制 Young 专用密码或新增解密持久事实。

共享新密文仅与成功核验的查询/导入、必要许可和审计同事务提交；保护、SQL、取消和失败保留旧事实。浏览器手填秘密不读取或保存，验证码、通行密钥和学校额外授权仍由用户完成。

## 后果与边界

- 共享密码不共享浏览器资产、业务身份 verifier 或认领许可；独立来源分区和全局互斥保持。
- 清二课登录资料保留两来源日程、共享密码和 JW 目录；删除保存的学校密码影响两来源，保留账号、分区和业务事实。
- 分区保留不承诺学校永久免登录。跨 Windows 用户/设备解密不作保证，界面不回填密码。
- 实际全自动化分别由 M1/M2 用户验收证明，不能从 JW 通过推定 Young 通过。规范依据见 [07](../architecture/07-constitution.md#学校账号与二课自动认证范围2026-10-11)与 [09 K-04](../architecture/09-contracts.md#k-04-作业凭据与交接)。
