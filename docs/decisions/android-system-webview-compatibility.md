# Android 普通系统 WebView 兼容修订

状态：**用户已批准，实施中**。编制与批准日期：2026-10-17。用户原话：“approve，请按项目工作流和修订后的兼容性修复计划开始实施，保留自动登录和采集功能。”本决定只修改 Android 学校浏览器的实现与相应信任边界，不改变 Windows1.00，也不代替 A7 真人验收或 A8 发行准入。

按[Android迁移计划](../milestones/android-apk/plan.md)中的 A7-W1–W6实施；本文件记录取舍，不另立第二份任务单。现行规则见[07](../architecture/07-constitution.md)、[09 K-01–K-05](../architecture/09-contracts.md)及[DR-ADR-09](dr-adr-09-browser-boundary.md)，冲突部分仅在本决定明确的Android映射内替代。

## 背景与依据

用户要求以普通系统 WebView 优先扩大兼容性，同时保留自动登录和采集。此前[兼容调研](../research/android-webview-compatibility.md)及[国内机型核对](../research/android-webview-domestic-models.md)说明，支持网页并不代表支持本工程设置的四项高级 API；不能从手机品牌、伪装机型、Android版本或 Chrome 版本推断这些 API 已具备。

当前 `ObservationBridge.ensureFeatures` 将 `MULTI_PROFILE`、`DELETE_BROWSING_DATA`、`DOCUMENT_START_SCRIPT`、`JS_INJECTION_IN_FRAME_AND_WORLD` 作为正常学校入口的必要条件；`ready` 又要求私有世界与全 frame 策略确认。`ScriptCatalog` 还依赖 Navigation API。MuMu实际为 Android12/API32、WebView110，之前的 API34/WebView113 样本同样缺少部分高级能力。SDK升级或改善报错不能让这些提供方自动获得完整学校通道。

因此，修复对象是浏览器宿主、就绪状态、脚本和恢复契约；不能只删除四项判断，沿用依赖它们的实现。

## 拟采用的路线

采用一个统一的**普通系统 WebView 后端**：固定学校脚本、单个按需学校宿主进程、按浏览器分区区分的数据目录，以及主进程持有的既有 C2/C3 控制。优先验证已知旧110/113提供方和现代提供方，不按厂商白名单放行，不要求用户安装指定版本的 Chrome/WebView。

- APK安装下限暂不改动，仍保留现行 API24配置。新学校宿主以 **API28/Android9起的目录后缀 API** 为技术下限候选，重点覆盖 Android10及以上、2024年后国内 ROM 和用户MuMu。API24–27暂不承诺完整学校自动同步；其它已成立能力保持。API28及所有目标提供方仍须实际验证，不从平台API存在推断完整可用。
- 不引入 GeckoView、X5 或自维护 Chromium 作为本轮第二条正式学校路径。若普通路线遇到真实不可替代阻塞，记录具体缺口再作取舍，不自动扩包或改用外部浏览器充当采集。
- 高级 API可以保留在诊断或旧资料恢复中，不能成为新普通路径的隐含必要条件。第一轮不维持两套正常作业状态机，也不将高级世界可用性改变为另一套产品权限。

### 能力门槛逐项处理

| 当前条件 | 拟处理 | 保证性质 |
|---|---|---|
| `MULTI_PROFILE` | 换为独立学校进程和每分区唯一随机 `setDataDirectorySuffix`；同一进程生命周期只用一个分区 | 保留来源/候选存储隔离目标，换实现并验证 |
| `DELETE_BROWSING_DATA` | 撤销、停止宿主、受控目录清理和恢复账本；无法确认删除时显示隔离待清理 | 删除实现替换；允许隔离残留继续新分区是下述 K-02 放宽 |
| `JS_INJECTION_IN_FRAME_AND_WORLD` | 普通页面世界执行随包固定脚本 | 明确放宽对恶意同源页面脚本的防护 |
| `DOCUMENT_START_SCRIPT` | 主文档加载与来源就绪后安装固定脚本；有界等待表单、SPA路由和helper | 不再要求先于页面脚本捕获原始对象 |
| 私有回复代理、精确旧文档投递 | 原生会话/文档世代与操作关联；秘密走限定 origin 的主框架消息 | 保留应用侧拒旧与单次消费，放宽秘密的精确文档保证 |
| Navigation API | 原生导航/历史通知、固定脚本的文档标记和操作前后检查 | 不设新 Web API硬门槛；不宣称标记能防同源伪造 |
| 所有 frame 的 document-start CSP 与 `frameReady` 门禁 | 取消本应用额外注入的全 frame CSP及全局握手，保留原生可观察的导航控制 | 明确缩小覆盖，不宣称覆盖所有子框架/重定向 |
| 清理 pending 阻断正常启动/新候选 | 已撤销、已停止、已隔离的残留作为可见清理待办；已验证独立的新分区可继续 | K-02有意放宽，业务所有权/撤销/排空失败不在此列 |

`setDataDirectorySuffix` 自 API28可用，须在该进程任何 WebKit初始化前设置，作用于数据和缓存路径；同一目录不得同时由多个进程使用。它不是在已初始化进程内随时切换 Profile 的 API。[Android官方API](https://developer.android.com/reference/android/webkit/WebView#setDataDirectorySuffix(java.lang.String))

## 学校宿主与资料生命周期

主进程继续独占目录所有权、数据库、C2共享租约、C3账号/密文/认领和导入事务。一个不导出的 `:school_host` 普通应用进程承载原生学校 Activity及受控服务，不初始化 FlutterEngine、Agent、SQLite、通知恢复或语音。它与主进程同UID，作用是生命周期与目录隔离，不称为抵御本应用原生代码入侵的安全沙箱。

每个分区绑定不可复用的随机后缀及后端版本。启动先持久登记映射、完成无秘密的宿主授权和目录选择，再初始化 WebView，并以跨进程宿主槽位排他锁阻止重复启动；切换教务、二课或候选分区必须停止旧宿主并确认排空后启动新实例，不在同一活进程更换后缀。学校 Activity可见时，主 Flutter Activity的暂停不能误判作业离开；整个应用后台、用户返回、父进程死亡、renderer退出和取消仍按既有作业规则收口。仅 Activity关闭、`destroy()`或 Binder断开均不独自证明排空完成。

账本只持生命周期元数据，新增 `backend/version`、分区引用、后缀、提供方及单调清理状态，不存账号、秘密或学校原文。认领仍在 C3提交后完成；IPC只接受固定操作和有效租约，不让学校页发起文件、数据库、凭据读取或任意导航。备份排除覆盖新增浏览器目录及恢复元数据。

### K-02 的拟议修订：隔离与物理删除分别记录

允许已持久撤销、执行体已停止且禁止重新使用的浏览器分区，在物理清理尚未完成时保持隔离待办。经验证与其存储隔离的新分区可以继续登录和同步，本地日程及不依赖故障学校通道的 Agent能力不受此类残留清理待办阻塞。只有受控范围实际删除并核验后才记清理完成。

必须保持以下区别：

1. **仅物理删除 pending 可以隔离后继续。** 撤销未持久化、旧宿主/执行体未停止、新旧存储隔离不明或旧提交资格未终止时，不得另开学校宿主绕过故障；共享宿主不可靠则两来源学校作业都暂停。
2. 新旧隔离采用平台后缀契约、AOSP实现核对及目标提供方的合成标记验证，不要求厂商另提供一个公开的取路径API。目录清理使用有依据的私有根和固定布局适配，不扫描认证内容，不猜测后删除未知目录。
3. `revoked/quarantined/deletePending` 标记跨升级/重启保留，旧后缀和许可永不重新认领。无法理解新状态的旧APK不能直接降级运行；回退验证只使用受控副本，不以资料丢失换回旧代码。
4. 残留状态持续可见，准确说明“登录资料已停用，旧浏览器资料仍待清理”。不能显示“清除成功”或“全部重置完成”。删除失败保留账本和可重试入口，不混同没有课程/活动。
5. 不因每次重试无限创建目录；健康已认领分区正常复用，对连续失败候选设置有限重试、数量和空间预算，超限暂停学校新建并说明原因。
6. C3/数据库、密钥、主进程所有权或可信撤销元数据恢复失败，仍按相应全局恢复规则处理。本修订不允许带未确定的事务或租约继续提交。

### 旧 AndroidX Profile 迁移

旧后端只保留恢复用途，不作为第二条日常采集路径。旧C3分区/许可、`.pending`和原生账本都保留归属；旧账本没有记录不证明没有资产。不得把新的后缀目录当作旧Profile已删除，也不迁移 Cookie、Token、浏览器存储或手填秘密。

升级可撤销旧浏览器许可、停止并隔离旧资料，然后在新后端重新登录。加密学校密码、账号绑定、学期目录、本地日程、任务、聊天、个人覆盖和已提交回执保留；已有保存密码时继续自动认证，不要求为切后端重新提供同一密码。

能调用旧SDK正确清理时沿用该路径；缺少旧能力时，若合成验证证明旧默认浏览器根完全归本应用且已排空，可提供一次**整体清除旧学校浏览器资料**的维护操作。该操作可能同时失效教务、二课浏览器登录状态，需明确范围；不会删除密码或业务资料。归属/布局不能可靠限定时保持隔离待清理，仍可在满足前述条件的新分区继续。本轮开发和测试不直接删除用户MuMu已有资料，也不通过卸载/清空应用数据解决迁移。

## 普通脚本、认证与采集的信任边界

拟信任获准学校HTTPS主文档及其执行的页面脚本，允许固定脚本在其普通页面世界运行。**不再承诺抵御已恶意化或被篡改的同源执行环境，也不承诺阻止密码被同源脚本观察。** 文档标记、随机nonce和世代只用于应用侧操作关联、拒旧和意外干扰检测，不是私有世界或浏览器签发的文档身份证明。

认证仍只使用固定 CAS origin/path、表单和操作：

1. 无秘密固定脚本检查顶层页面、`https://id.ustc.edu.cn/cas/login`、唯一表单/输入框、固定提交目标及挑战状态。
2. 原生复核租约、宿主实例、分区、世代、当前URL和本次准备操作；在投递前消费一次性凭据租约。
3. 优先采用 API23起已有的 `WebView.postWebMessage`，以精确 `https://id.ustc.edu.cn` 为 `targetOrigin` 向主框架投递，秘密不拼进 `evaluateJavascript`源码，不使用通配origin或页面可调用的“取密码”接口。
4. 固定接收逻辑复核当前路径、文档/操作标记、表单和挑战后提交。确认未知不重发；导航、取消和关闭撤销后续动作，验证码和学校额外授权仍由用户处理。

原生消息限定的是 origin，不是路径或具体文档；不能保证同源错误/旧文档绝不观察到秘密，也不能凭网页里的 `event.origin/source` 将发送方认证为本应用。一次性端口如有采用，仍须验证生命周期，不能据此恢复旧私有世界的强保证。[官方消息语义](https://developer.android.com/reference/kotlin/android/webkit/WebView.html#postWebMessage(android.webkit.WebMessage,android.net.Uri))、[官方桥接边界](https://developer.android.com/develop/ui/views/layout/webapps/native-api-access-jsbridge)

JW/Young仍通过各自固定业务响应核验预期本人身份，保留读取前后匹配、范围/分页完整性、北京时间、白名单投影和事务交付。Young在页面和helper就绪后安装本次读取器，主动触发固定GET，并关联本次fetch/XHR响应实例；后台同URL请求、无传输的伪helper返回对象、歧义/迟到/跨步响应不交付。若helper预先缓存底层引用导致无法观察，返回具体兼容故障，不以页面自报对象冒充身份结果。普通世界下捕获的函数可能已经被页面包装，因此传输关联是在上述学校页面可信前提下取得业务证据，不是独立抵御恶意同源脚本的网络证明。

保留闭合操作集，不开放任意JS、URL、HTTP参数或通用原生桥。同步结果通过固定 `evaluateJavascript`回调，异步读取采用固定的有界轮询；不要求页面主动调用任意Java接口。不读取或复制 Cookie/Token/认证头到Dart或原生HTTP，不抓包记录学校原始响应。

## 导航、frame与权限

取消本应用为全frame提前注入的附加CSP及其就绪门槛，不移除学校自身CSP。保留主动导航前检查、原生可观察导航/文档请求检查、未知主页面停止自动操作、弹窗同分区受控收口、外部协议/下载/网页原生权限默认拒绝；凭据与采集仅面向登记的顶层页面。

普通WebView回调不能完整覆盖所有子框架、POST、opaque/blob/srcdoc和中间重定向；本方案明确接受普通浏览器同源策略和站点自身策略作为这些情形的边界，不宣称原全frame封闭保证。页面正常资源请求和Worker仍遵循DR-ADR-09，不增加全协议拦截、全局禁Worker或额外浏览器内核资格门槛。[WebViewClient官方限制](https://developer.android.com/reference/android/webkit/WebViewClient)

HTTPS、证书错误拒绝、混合内容/本地文件限制继续保留；不开启忽略证书、任意host或绕过TLS验证来提高兼容率。

## 后果与批准范围

预期收益是旧系统组件不再仅因缺四项高级API而拒绝学校作业，自动登录与采集继续成为完整交付目标。代价是增加一个受控学校进程及目录生命周期实现，接受同源页面脚本可信、frame覆盖缩小，以及明确可见的隔离残留待清理状态；这些不是原契约的等价安全增强。

用户批准后只在Android落实对应的07/09/10/11/12/13与来源执行环境说明，Windows的既有文档绑定/浏览器实现保持。A0–A7历史失败与通过记录不改写；新路线按新的测试矩阵验收，目标机、真实学校和鸿蒙结论仍需后补。具体步骤、文件边界和验收唯一维护于迁移计划。
